## 1. 背景与问题陈述

### 1.1 三大矛盾（BC-1 ~ BC-3）

> 下表「量化基线」为上游 v2.0 案例评审与领域调研所得的**现状基线数**，用于把定性痛点转为**可复测**的验收前提；每条矛盾在 v2.1 中被转化为一个或多个目标（G-n）与验收标准（AC-n）。

#### BC-1 策略语言碎片化与「点测试」局限

**陈述**：各业务域（云服务部署、金融合规、交易风控、电商营销）各自使用互不通用的配置/规则格式——云部署用 YAML/HCL，合规用 DMN，风控用 DRL，营销用 JSON。每种格式配一套独立的校验工具，跨域复用率为 0，导致验证基础设施被重复建设 4 次。既有校验工具（Linter、OPA）只能对**单份确定配置**做布尔求值（point evaluation），无法对**全量参数空间与规则集本身**做数学完备性证明。

| 量化基线 | 数值 | 后果 |
|---|---|---|
| 领域格式数 | 4（YAML/HCL、DMN、DRL、JSON） | 校验栈重复建设 4 套 |
| 跨域复用率 | 0% | 每新增领域需从零重建验证设施 |
| 单实体参数空间 | `Service` 实体 8 字段，仅 `port∈[1,65535] × subnet_id∈[1,10]` 即 ≥ 6.5×10⁵ 组合 | 点测试无法穷尽 |
| 抽样覆盖率 | 以 500 条规则、每规则 10³ 次抽样计，对 ∀-量化命题的覆盖 ≤ 10⁻³ | 「测试通过」≠「命题成立」 |

**→ 派生目标**：`G-1` `G-2` `G-3`；**→ 派生验收**：`AC-1` `AC-2` `AC-3` `AC-8`。

#### BC-2 形式化验证门槛高与可判定性失控

**陈述**：Z3、CVC5、Bitwuzla、TLA+、Lean 各有输入格式与理论适用边界。业务人员不懂 SMT-LIB2，研发人员不懂一阶逻辑**可判定性（Decidability）**与**量词消除（Quantifier Elimination）**。一旦引入非线性算术（`QF_NIA`）或无界量词，求解器极易超时或挂起，团队被迫以抽样测试代替数学证明。上游 v2.0 案例中：

| 量化基线 | 数值 | 后果 |
|---|---|---|
| 工具输入格式数 | ≥ 5（SMT-LIB2 / TLA+ / Lean / 各求解器方言） | 学习与维护成本高 |
| 无静态守卫时超时率 | 构造场景 ≥ 30% 的查询超时或挂起 | 无结论、无法门禁 |
| 非线性样例 | `s.port * s.id > 1000` 落入 `QF_NIA`，无 timeout 时可挂起 > 60 s | 编译期零拦截 |
| 可判定性静态守卫 | 0（v2.0 仅有口号「100% 无量词」，无度量、无预算） | `size: 100` 的 `∀∀` 规则静默产生 10⁴ 子式 |

**→ 派生目标**：`G-4` `G-5` `G-8`；**→ 派生验收**：`AC-4` `AC-5` `AC-6` `AC-10` `AC-11` `AC-12`。

#### BC-3 验证与治理脱节

**陈述**：即便编写了形式化验证脚本，结果也散落本地，缺乏版本管理、策略演进对比（Subsumption）、最小冲突溯源（Unsat Core）与 CI/CD 自动化门禁。规则被二次修改后未经过形式化回归，验证形同虚设。

| 量化基线 | 数值 | 后果 |
|---|---|---|
| 验证脚本版本化率 | 0% | 结果不可追溯 |
| Unsat Core 溯源 | 无（v2.0 仅「提及」） | 冲突规则无法定位 |
| CI 门禁覆盖率 | 0%（无门禁脚本） | 违规策略可合入 |
| 变更→验证自动触发率 | 0% | 回归靠人工自觉 |
| 审计报告可复算率 | 0%（无 `proof_hash`） | 无法离线复算判定 |

**→ 派生目标**：`G-6` `G-7`；**→ 派生验收**：`AC-7` `AC-9`。

### 1.2 现有方案的局限（LU-1 ~ LU-5）

| ID | 方案 | 局限 |
|---|---|---|
| `LU-1` | AWS Cedar | 仅面向访问控制（Authorization）领域；语法固定为 `principal` / `action` / `resource` 原语，**无法定义跨实体的架构拓扑与通用领域约束** |
| `LU-2` | AWS Zelkova | AWS 内部闭源服务；仅面向 IAM 与 S3 策略分析，**外部无法复用其底层 SMT 转换与求解器编排管线** |
| `LU-3` | Dafny / F* | 面向通用编程语言的形式化验证工具；关注算法与程序规约，**而非声明式策略语言元框架** |
| `LU-4` | Alloy | 学术化关系建模工具；语法抽象，**缺乏多求解器竞速、SMT 理论路由与工程级 CI/CD 治理闭环** |
| `LU-5` | OPA / Rego | 运行时策略求值引擎（点评估）；**不支持全空间反例求解、策略包含性证明与 Unsat Core 死锁归因** |

### 1.3 核心缺口与结论

**核心缺口**：缺乏一个**开源的、领域无关的**、支持用户自定义领域本体（`Entity` / `Domain`）与约束结构、并能自动完成**有界域展开**与**多求解器并行证明**的策略语言元框架。

**结论**：本项目目标是构建通用化的策略语言定义与形式化验证元框架（开源版通用 Zelkova）：让用户定义自己的领域本体与约束（DSL），框架在编译期执行**可判定性静态守卫**与**有界量词展开**，可信编译为**无量词 SMT-LIB2**，通过**理论感知的并行求解器竞速**完成验证，并将**反例模型（Model）**或**最小冲突核（Unsat Core）**逆向翻译为业务可读诊断。它不是又一种单一领域的策略语言，而是**生产与验证策略语言的标准化产线**。

## 2. 目标与非目标

### 2.1 目标（In Scope，G-1 ~ G-8）

> **纪律**：每条目标必须给出**可证伪的衡量标准**——即存在一个有限测试断言其为真或为假。

| ID | 核心目标 | 可证伪的衡量标准 |
|---|---|---|
| `G-1` | 领域无关的本体建模 | 同一二进制 `policylang verify` 在 `examples/` 中 **3 个**完整案例（`cloud-deployment.plm`、`exchange-compliance.plm`、`marketing-coupon.plm`）上均可生成 SMT-LIB2 并返回确定判定（`sat`/`unsat`）；新增第 4 个领域**无需修改** `policylang-parser` / `policylang-check` 源码 |
| `G-2` | 有界域自定义变量 | 六个排序 `Int` / `Real` / `Bool` / `Str` / `Enum(E)` / `BV(n)` 与结构化 `Set[E] [size:N]` 全部通过 `W1`–`W3` 检查；缺界一律以 `E-MISSING-RANGE` 阻断（`03 §3.3`） |
| `G-3` | 完备的规则组合与证明演算 | 六式验证目标 `consistency` / `invariant` / `refines` / `completeness` / `safety` / `mutex`（`FR-3`）均为独立 CLI 子命令并各有 ≥ 1 正向 + ≥ 1 反例测试；`matches_all` 支持正则交集、`in_cidr` 支持 IPv4/IPv6 |
| `G-4` | 可判定性守卫与可信编译 | (a) 非线性和无界构造的**编译期拦截率 = 100%**（以 `AC-4` 与 `06 §6.6` 的全量 negative corpus 计）；(b) 通过检查的规范，`ground(φ)` 输出**不含任何 `forall`/`exists` 记号**（`TH-2`，由 `TH-2-C1` 保证 `set-logic` 以 `QF_` 开头）；(c) 该断言成立以 `W11`（`G(φ) ≤ G_max`）通过且未启用 `--allow-nonlinear` 为前提（`03 §3.8`）；(d) **核心算子的 Lean 4 语义保序证明按里程碑分层交付**：`TH-1-C2`（反例可唯一还原）与 `TH-2`（量词消除）在 `M-2` 达**零 `sorry`**（`TH-1`/`TH-1-C1` 随 `OBL-1` 闭环零 `sorry`）；`TH-4`（除法线性化）与 `TH-6`（正则转译）在 `M-4`、`TH-5`（CIDR 掩码）在 `M-6` 达零 `sorry`（`12 §12.6.2`）；编码充分性定理 `TH-7` 的机械化在 `M-6` 完成。零 `sorry` 部分为**硬验收证据**，冻结陈述 + 证明计划为软证据，硬门禁范围由 `OQ-9` 裁决 |
| `G-5` | 理论感知的并行求解竞速 | (a) 逻辑档位由 `T(φ)` 推导且经能力探测校核（`TH-3a` / `ALG-3`）；(b) 首胜后其余子进程回收 **P99 ≤ 50 ms**（`AC-5`）；(c) 展开后断言数 = 500 且 `G ≤ G_max` 时，P99 求解延迟 **< 3 s**（`NFR-1`） |
| `G-6` | 双向可解释诊断（Model & Core） | SAT 时模型经 `ground` 逆映射（`TH-1-C2`）还原为 `Services[i].field = 业务值`（IP 转点分十进制）；UNSAT 时 `(get-unsat-core)` 经 `:named` 映射回 `rule` 名与源码行；两条路径各有端到端测试 |
| `G-7` | 治理闭环与 CI/CD 门禁 | 每次验证产出含 `proof_hash`（`TH-10`）与行号映射的结构化报告；CI 门禁脚本**显式覆盖全部 5 个 `overall_status` 分支**（`00 §0.4.4`），`Fail` 阻断、`UnknownReviewRequired` 转人工 |
| `G-8` | UNKNOWN 诚实阻断处理 | 全求解器超时/`unknown` 时，`overall_status = UnknownReviewRequired`、CLI 退出码 **2**；**断言存在测试**证明任何 `unknown` 路径都不会产生 `Pass`（`TH-7 (iii)`） |

### 2.2 非目标（Out of Scope，NG-1 ~ NG-4）

| ID | 非目标 |
|---|---|
| `NG-1` | **不做图灵完备的策略语言**：严禁无界递归、无界循环、PCRE 回溯断言（前瞻/后顾/反向引用/占有量词）及任意宿主脚本嵌入（对应 `03 §3.13.2` 拒绝清单） |
| `NG-2` | **不做运行时策略执行引擎**：本框架仅负责编译期与发布前的静态数学证明；运行时实时拦截交由网关插件、OPA 或业务执行器负责 |
| `NG-3` | **不做通用编程语言验证**：不验证含堆内存指针与并发副作用的通用代码，仅验证声明式策略与配置约束 |
| `NG-4` | **不内置重型图形画布**：v2.1 聚焦 DSL 编译器、求解器编排器与 CLI 门禁；可视化画布留待后续版本 |

> **边界说明**：`NG-2` 使本框架与运行时执行引擎（OPA / LiteFlow / 网关插件）**正交解耦**，专注解决「规则与配置本身的数学正确性」；`NG-3` 使验证目标限定为声明式策略而非通用程序；`NG-1` 使语言上限严格停在**正则语言 + 一阶逻辑可判定片段**。三者共同界定：`G-1` 的「领域无关」**不等于**「任意程序可验证」。

## 3. 架构哲学

### 3.1 四层分离架构与层间契约

```
┌──────────────────────────────────────────────────────────────────────┐
│ 1. 语言层（Language Layer）  crate: policylang-parser / policylang-ast│
│    - 领域实体本体（Entity / Finite Domain）声明                        │
│    - 有界变量声明与类型约束（Int / Real / Bool / Str / Enum / BV(n)）  │
│    - 策略规则（Policy Rules）、安全不变量（Invariants）与分支声明       │
│    - 五式验证目标声明（Consistency / Invariant / Refines / Complete / Safety）│
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ 契约 L→C: 强类型 AST + Span（`.plm` 源码）
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 2. 编译层（Compiler Layer）  crate: policylang-check / policylang-codegen│
│    - Pest 语法解析 ──► 强类型 AST                                     │
│    - 符号表绑定、类型检查 + 可判定性静态守卫（W1–W12 / Decidability Guardian）│
│    - 有界量词单态化展开（ALG-1 ground，消除 forall/exists）             │
│    - 逻辑特征探针（推导 QF_BV / QF_SLIA / QF_LIA / …，经 TH-3a 校核）  │
│    - 可信 SMT-LIB2 生成（注入 :named 溯源标签 + 反证查询 + get-model/core）│
│    - 诊断逆向翻译器（S-Expr Model / Unsat Core ──► 业务实体报告）       │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ 契约 C→S: 标准 SMT-LIB2 查询 + 逻辑档位标签
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 3. 求解层（Solver Layer）  crate: policylang-solver                   │
│    - 理论感知路由器（Theory-Aware Router，规避「求解器不支持该理论」报错）│
│    - 进程级隔离并行竞速编排（Z3 / CVC5 / Bitwuzla）                    │
│    - 首胜即止（Winner-Takes-All + 其余子进程强杀回收）                  │
│    - 跨求解器模型一致性交叉验证（Cross-Validation）                    │
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ 契约 S→G: 判定 + 反例/冲突核 + 耗时/求解器元数据
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 4. 治理层（Governance Layer）  crate: policylang-governance / policylang-cli│
│    - 策略版本演进对比（Semantic Diff & Subsumption）                   │
│    - CI/CD GitOps 门禁集成与退出码控制（0–4）                          │
│    - 审计追溯（proof_hash 存证）与 UNKNOWN / Waiver 人工审批流         │
└──────────────────────────────────────────────────────────────────────┘
```

**层间契约（Layer Contracts）**

| 契约 | 方向 | 输入 | 输出 | 违约处置 |
|---|---|---|---|---|
| `L→C` | 语言层 → 编译层 | `.plm` 源码文本 | 强类型 AST（含 `Span`）+ 声明依赖图 | 解析失败 `E-PARSE`，退出码 3 |
| `C→S` | 编译层 → 求解层 | 逻辑档位 + SMT-LIB2 脚本 | 判定 + 模型/核文本 | 守卫失败 `E-*`，退出码 3；不进入求解 |
| `S→G` | 求解层 → 治理层 | 判定 + 元数据 | `overall_status` + 报告 JSON | 交叉验证不一致 `E-CROSSVAL-MISMATCH`，退出码 4 |
| `G→外部` | 治理层 → CI/审计 | 报告 JSON | 退出码 + SARIF | 报告落盘失败 `E-REPORT-IO`，退出码 4 |

### 3.2 与 Cedar / Zelkova 的架构对标

> 三维列（**验证能力边界** / **不可判定性处理** / **治理闭环**）为 v2.1 新增，用于显式界定本框架能力与不可判定性的诚实边界。

| 维度 | AWS Cedar | AWS Zelkova | PolicyLang Meta（本项目） |
|---|---|---|---|
| 定位 | 访问控制策略语言 | IAM 策略形式化分析服务 | 通用策略语言定义与形式化验证元框架 |
| 适用领域 | 权限鉴权（RBAC/ABAC） | 云 IAM / S3 权限配置 | 领域无关（云原生拓扑、金融合规、风控配置） |
| 原语结构 | 固定（`principal`/`action`/`resource`） | 固定（IAM JSON 结构） | 可组合一阶逻辑原语 + 自定义实体本体 |
| 用户自定义 | 仅限属性扩展 | 不支持自定义领域 | 完全支持自定义实体、有界变量与规则结构 |
| 开源状态 | 开源 | 闭源 | 开源（元框架，允许二次开发领域前端） |
| 验证能力 | 单策略求值 + Lean 证明 | 多 SMT 求解器组合证明 | 有界展开（`ALG-1`）+ 理论感知多 SMT 竞速 + Unsat Core |
| **验证能力边界** | 限于访问控制语义；不可表达跨实体拓扑不变量 | 限于 IAM/S3 可编码片段；外部不可扩展 | 限于**可判定片段 `T(φ)`**（`TH-3`）：无量词 + 每理论可判定；跨理论组合受 `TH-3a` 限定 |
| **不可判定性处理** | 语义上规避（语言本身不含不可判定构造） | 闭源内部策略，未公开 | 编译期静态守卫 100% 拦截（`W8`/`W9`/`W11`）；组合逻辑经 `ALG-3` 能力探测，失败标记 `UNKNOWN_RISK` 且**只接受 `UnknownReviewRequired`**（`DD-3.2`） |
| **治理闭环** | 语言内建，治理工具另配 | AWS 托管内部闭环 | 内建 `proof_hash` 审计 + CI 门禁 5 码制 + Waiver 状态机（`FR-13`/`FR-18`/`FR-19`） |

### 3.3 架构级不变量（INV-L1 ~ INV-L5）

> 下列不变量是**跨层**的架构约束，任一违反即视为架构回归；每条绑定一个可测试断言。

| ID | 不变量 | 绑定测试 |
|---|---|---|
| `INV-L1` | **层序单向**：语言层不依赖编译/求解/治理层；编译层不依赖求解/治理层；求解层不依赖治理层（由 Cargo 工作区依赖图强制） | `cargo tree` 无反向依赖边 |
| `INV-L2` | **单一命名实现**：`scalar_symbol` / `domain_instance` 在全工作区**仅有一处实现**，声明发射器与 `ground` 复用同一函数（`03 §3.6.2`） | 源码静态检查 + 命名一致性差分测试 |
| `INV-L3` | **诚实阻断**：`unknown` 在任何路径都不得坍塌为 `Pass`；`overall_status` 由合并格 join 得出（`00 §0.4.2`） | `AC-6` + 全路径注入测试 |
| `INV-L4` | **可复算性**：`ground` 为纯函数（`DET-1`），`proof_hash` 与 `query_hash` 可离线复算 | `AC-9` |
| `INV-L5` | **编译期不求解**：任何未通过 `W1`–`W12` 的规范不得生成 SMT-LIB2、不得启动求解进程 | `AC-4`；进程监控测试 |

#### FR-1 领域实体与有界变量声明

- **需求陈述**：用户可声明结构化实体 `entity E { field: Sort [constraint], … }`、有限集合域 `domain D: Set[E] [size: N]` 与全局独立变量 `var v: Sort [constraint]`。
- **形式化定义 / 依据**：`03 §3.2`（排序签名 3.2.1、语义载体 3.2.2、记录模式定义 3.2.1、实例域定义 3.2.2、展平定义 3.2.3）；合式性 `W1`–`W4`。
- **SMT 编码要点**：每个实例字段展平为注入常量 `scalar_symbol(D,i,f) = "PL_" + escape(D) + "_" + dec(i) + "_" + escape(f)`（`03 §3.2.3`）；边界断言 `Bnd(S)` 由受限载体特征谓词全合取生成且**不带 `:named`**（`DD-3.1`）；`Set[E]` 于编译期单态化展开为 `N` 组独立标量。
- **验收要点**：`AC-1`、`AC-12`；缺界/空载体必须阻断。
- **错误码**：`E-BAD-SORT`（`W1`）、`E-MISSING-RANGE`（`W2`）、`E-EMPTY-CARRIER`（`W3`）、`E-UNKNOWN-ENTITY` / `E-DUP-SYMBOL`（`W4`）；均退出码 3。

#### FR-2 策略与规则声明

- **需求陈述**：用户以 `policy P { rule R: φ … }` 组织命名规则，以 `invariant I { φ }` 声明全局安全红线；支持布尔原子（`field_access` 直接作为公式）。
- **形式化定义 / 依据**：`03 §3.4.2`（`T-BOOL-ATOM` 布尔原子产生式，【补全 B-2】修复上游文法无法解析 `s1.uses_db and s2.uses_db` 的自相矛盾）；`W12`（被验证策略非空）。
- **SMT 编码要点**：每条规则的断言注入 `(assert (! φ_i :named Rule_<name>))`，`:named` 与源码 AST 节点一一映射；`policy` 的语义为其规则合取 `R_P ≜ ⋀{ ⟦ground(r)⟧ ∣ r ∈ rules(P) }`。
- **验收要点**：`AC-2`；空策略必须阻断，不得放行（否则 `consistency` 恒 SAT、`refines` 恒 FAIL，语义退化）。
- **错误码**：`E-EMPTYPOLICY`、`E-UNKNOWN-TARGET`（`W12`）、`E-CYCLIC-DECL`（规则/声明依赖存在环，`03 §3.3.1 D-1`）；均退出码 3。

#### FR-3 验证目标声明（六式）

- **需求陈述**：用户声明六类验证目标：`consistency of P`、`invariant I under P`、`P_new refines P_old`、`completeness of P`、`safety of P`、`mutex of P`。`completeness`（全覆盖）与 `mutex`（两两互斥）联合构成「分支是输入域的一个划分」这一更强性质。
- **形式化定义 / 依据**：`03 §3.14`（`TH-7` 编码充分性总纲）与 `06 §6.3`（逐式编码表）；`safety` 见 `03 §3.11.2`/`§3.11.5`。
- **SMT 编码要点**：反证法编码 `Γ ∧ ¬φ`；`consistency` 判 SAT=通过、UNSAT=失败（提核）；`invariant`/`refines` 判 UNSAT=通过、SAT=失败（提模型）；`refines` 为双查询（`06 §6.3.3`）；`completeness` 归约为 `branch` 化（`03 §3.3.1`）；`safety` 查询本身不含除法（`03 §3.11.5`）。
- **验收要点**：`AC-1` `AC-2` `AC-3` `AC-11` `AC-12`；六式各有正向与反例测试。
- **错误码**：`E-UNKNOWN-TARGET`（目标引用的策略/不变量/域/`branch` 未声明）；退出码 3。

#### FR-4 Parser 与强类型 AST

- **需求陈述**：用 Pest 解析 `.plm` 源码，生成携带源码行列跨度（`Span`）与类型签名的强类型 AST；AST 可无损序列化为标准 JSON（`ast_schema_version: "1.0"`）。
- **形式化定义 / 依据**：`05 §5.2`、`spec/grammar.pest`；运算符优先级遵 `03 §3.4.3`（含【补全 B-3】新增 `iff` 最低优先级产生式）。
- **SMT 编码要点**：本 FR 不直接产出 SMT；AST 是 `policylang-check` 与 `policylang-codegen` 的唯一输入。
- **验收要点**：往返序列化 `parse(serialize(ast)) = ast`；`Span` 精确定位到行列；`iff` 与布尔原子均可解析。
- **错误码**：`E-PARSE`（词法/语法错误，携带 Span）；退出码 3。

#### FR-5 符号表检查与可判定性静态守卫（Decidability Guardian）

- **需求陈述**：类型推断与校验（字段引用存在性、两侧排序一致、范围合法）；遍历 AST 拦截非线性、无界量词、非正则正则；最终判定为 `Unverifiable` 者**编译期直接阻断**。
- **形式化定义 / 依据**：`03 §3.3`（`W1`–`W12`）、`03 §3.4.1`（线性性侧条件 `LinMul(a,b) ≜ isConst(a) ∨ isConst(b)`，除法侧条件独立要求常量除数，【补全 A-8/C-5】修复上游漏检 `2 / x`）、`03 §3.9.2`（`W11` 预算）。
- **SMT 编码要点**：同时统计运算符特征以推导逻辑档位 `LogicProfile`；`G(φ)` 由 AST 在 `O(|φ|)` 内静态算出，不执行展开。
- **验收要点**：`AC-4`；100% 拦截率（以负例语料计）。
- **错误码**：`E-SORT-MISMATCH`、`E-UNBOUND-VAR`、`E-UNBOUND-INSTANCE`、`E-UNKNOWN-FIELD`、`E-NONLINEAR`、`E-REGEX-NONREGULAR`、`E-REGEX-UNSUPPORTED`、`E-REGEX-BUDGET`、`E-CIDR-WIDTH`、`E-CIDR-SYNTAX`、`E-GROUNDING-BUDGET`、`E-CROSS-DOMAIN-REF`、`E-UNVERIFIABLE`；均退出码 3。

#### FR-6 有界量词单态化展开与 SMT-LIB2 可信翻译

- **需求陈述**：在编译层将 `forall` / `exists` 按 `domain` 的 `size` 展开为无量词合取/析取；每条规则断言附带 `:named` 溯源标签并与 AST 映射，保障可审计。
- **形式化定义 / 依据**：`03 §3.6`（`ALG-1 ground`）、`03 §3.7`（`TH-1` Grounding 保持）、`03 §3.8`（`TH-2` 量词消除）。
- **SMT 编码要点**：枚举顺序取 `Fin N` 元组**字典序**（`DET-1`，保证 `ground` 为纯函数、`query_hash` 可复算）；实现 `FOLD-1`（常量折叠）、`FOLD-2`（α-等价去重）、`CSE-1`（公共子式 `let`）、`ALG-1-P`（部分出现剪枝）；声明发射器与 `ground` 严格复用同一 `scalar_symbol` 函数（`03 §3.6.2`，【补全 B-9】）。
- **验收要点**：`AC-1` `AC-6`；输出不得含 `forall`/`exists`。
- **错误码**：`E-GROUNDING-BUDGET`（`G(φ) > G_max`，携带量词嵌套路径诊断 JSON）；退出码 3。

#### FR-7 反例模型与冲突核心逆向翻译

- **需求陈述**：SAT 时把 SMT 模型中的扁平标量逆向聚合为业务实体视图并生成修复建议；UNSAT 时把 `(get-unsat-core)` 返回的符号映射回具体规则名与源码行。
- **形式化定义 / 依据**：`03 §3.7`（`TH-1-C2` 反例可唯一还原）、`06 §6.8`（响应解析与核心归因）、`07 §7.4`。
- **SMT 编码要点**：逆映射按 `scalar_symbol` 的 `escape` 逆函数解析 `flat(D,i,f)`；`BV(32)` → 点分十进制、`Enum` → 成员名、`Real` → `num/den` 精确有理数（**严禁** IEEE-754 参与重放，`03 §3.2.3 N-1`）。
- **验收要点**：`AC-1` `AC-2`；`Services[0].host_ip = "10.0.1.5"` 与规则行号均正确。
- **错误码**：`E-EMPTY-CARRIER`（`Bnd(S)` 自身不可满足导致核为空，须报此码而非「空核」）；退出码 3。

#### FR-8 理论感知路由与并行求解器竞速编排

- **需求陈述**：根据 AST 特征生成最精确的 `(set-logic …)` 头部并仅分发给支持该理论的求解器；每求解器为独立 OS 子进程，首胜后立即强杀其余进程。
- **形式化定义 / 依据**：`03 §3.10.3`（`TH-3a` 组合逻辑限定 + `DD-3.2`）；`ALG-3 probe_logic`（`06 §6.4`）。
- **SMT 编码要点**：`QF_SLIA` 任务仅分发 Z3 与 CVC5（屏蔽 Bitwuzla）；纯 `QF_BV` 优先 Bitwuzla、Z3、CVC5；组合逻辑档位经能力探测实测，探测失败标记 `UNKNOWN_RISK`，该目标**只接受 `UnknownReviewRequired`**。
- **验收要点**：`AC-5`；首胜回收 P99 ≤ 50 ms，子进程残留率 0。
- **错误码**：`E-SOLVER-MISSING`（无任何兼容求解器可用）；退出码 4。

#### FR-9 增量验证与结果交叉验证

- **需求陈述**：支持**单求解器会话内**基于 `(push)`/`(pop)` 的增量求解，用于 (a) `--incremental-single-solver` 批量排查、(b) Unsat Core 最小化（`06 §6.9.2`）。**不再要求**「单文件多验证目标 + 竞速」并存（该组合与首胜强杀冲突，见 `06 §6.1.3` 与 `09 §9.3 C-1`）。多目标批量由**目标级并行调度**承载（`FR-20`）。交叉验证：`sat` 走独立模型重放（`06 §6.7.1`），`unsat` 走多后端一致或 Alethe 证明检查（`06 §6.7.2`）。
- **形式化定义 / 依据**：`03 §3.14`（`TH-7` (i)/(ii) 可靠性）、`06 §6.7`（模型重放）。
- **SMT 编码要点**：`(push)` / `(pop)` 复用一个求解上下文；模型重放以精确算术逐位重算全部断言，不许浮点。
- **验收要点**：`AC-5`；交叉验证不一致必须报错，不得静默采信任一方。
- **错误码**：`E-CROSSVAL-MISMATCH`（两求解器判定或模型互斥）；退出码 4。

#### FR-10 UNKNOWN 诚实处理机制

- **需求陈述**：当所有求解器均超时或返回 `unknown` 时，系统诚实输出 `UnknownReviewRequired` 与耗时明细；严禁视为验证通过，CI 门禁返回非零退出码并触发人工评审。
- **形式化定义 / 依据**：`03 §3.14`（`TH-7 (iii)`：`unknown` 不作任何断言）；`00 §0.4.1`–`§0.4.3`（状态与退出码）。
- **SMT 编码要点**：响应解析状态机（非按行）须把 `unknown` 与 `(error …)` 明确区分；`overall_status` 由合并格 `Error ⊐ Fail ⊐ UnknownReviewRequired ⊐ Waived ⊐ Pass` 取最大者。
- **验收要点**：`AC-6`；`1 ms` 超时场景退出码为 2。
- **错误码**：状态 `UnknownReviewRequired`；退出码 2。

#### FR-11 策略即代码（Policy as Code）

- **需求陈述**：策略 DSL 与验证目标统一纳入 Git 版本控制；支持通过 `refines` 原语在 PR 阶段自动对比新旧策略的语义收敛性（`P_new ⟹ P_old`）。
- **形式化定义 / 依据**：`03 §3.14` 与 `06 §6.3.3`（`refines` 双查询 `Q1`/`Q2`）；`00 §0.3.2`（语义收敛、策略包含性）。
- **SMT 编码要点**：`refines` 编码为对 `P_new ∧ ¬P_old` 的 SAT 查询；SAT 时提取模型展示「被意外放行的边界」。
- **验收要点**：`AC-3`；新策略扩大暴露面时必须拦截。
- **错误码**：`E-UNKNOWN-TARGET`（策略名未声明）；退出码 3。

#### FR-12 CI/CD 门禁集成

- **需求陈述**：提供标准化 CLI `policylang`；验证通过返回退出码 0，发现反例/冲突返回 1，超时/UNKNOWN 返回 2，编译阻断返回 3，内部错误返回 4。
- **形式化定义 / 依据**：`00 §0.4.3`（5 码制，其中 3/4 为 v2.1 新增）、`00 §0.4.4`（`overall_status` JSON 序列化）。
- **SMT 编码要点**：无（本 FR 消费判定结果）。
- **验收要点**：`AC-4`（退出码 3）、`AC-6`（退出码 2）、`AC-7`；门禁脚本必须显式覆盖全部 5 个分支（v2.0 的 3 分支脚本会把 `Error` 误判为 `Fail`，见 `09 §9.2 B-16`）。
- **错误码**：`E-REPORT-IO`（报告落盘失败）、`E-SOLVER-VERSION`；退出码 4。

#### FR-13 审计追溯与存证

- **需求陈述**：每次验证输出结构化 JSON 审计报告，包含策略源码 SHA-256、生成的 SMT-LIB2 摘要、胜出求解器名称、执行耗时及 `proof_hash`。
- **形式化定义 / 依据**：`07 §7.5`（`TH-10` 审计哈希确定性）、`00 §0.3.2`（溯源自证哈希 / 运行证明哈希）。
- **SMT 编码要点**：`proof_hash = SHA-256(规范哈希 ‖ 查询哈希 ‖ 判定结果)`；`query_hash` 因 `DET-1` 的字典序枚举而可离线复算；`attestation_hash` 额外覆盖胜出求解器、耗时、宿主信息。
- **验收要点**：`AC-9`；`proof_hash` 100% 可复算，规则行号 100% 映射。
- **错误码**：`E-REPORT-IO`；退出码 4。

#### FR-14 正则子语言转译器（PCRE 子集 → SMT-LIB `RegLan`）【v2.1 新增】

- **需求陈述**：把 `matches_all [r̄]` 中的模式从受限 PCRE 子语言 `R_sub` 转译为 SMT-LIB `RegLan` 表达式；对子语言外构造按拒绝清单区分「非正则」（`E-REGEX-NONREGULAR`）与「正则但 `RegLan` 无对应」（`E-REGEX-UNSUPPORTED`）。
- **形式化定义 / 依据**：`03 §3.13`（`R_sub` 映射表 `τ` 见 3.13.1、拒绝清单见 3.13.2、定理 `TH-6` 语言保持见 3.13.3）；合式性 `W9`。
- **SMT 编码要点**：`matches_all [r₁,…,r_k]` 编码为 `(str.in_re e (re.inter τ(r₁) (re.inter τ(r₂) …)))`（`TH-6-C1`）；`k = 0` 退化为 `⊤`；一律显式 `str.to_re "c"` 而非裸字串隐式强制，保证跨求解器可移植；计数构造 `r{n,m}` 要求 `n·|τ(r)| ≤ 4096`，否则 `E-REGEX-BUDGET`。
- **验收要点**：`AC-10`；`L(τ(r)) = L(r)`（`TH-6`）以差分测试抽样验证。
- **错误码**：`E-REGEX-NONREGULAR`、`E-REGEX-UNSUPPORTED`、`E-REGEX-BUDGET`；退出码 3。

#### FR-15 `distinct` 量词修饰与分支/互斥声明【v2.1 新增】

- **需求陈述**：支持 `forall x̄ in D distinct: φ` / `exists x̄ in D distinct: φ`，以**单射枚举**语义表达「两两互异」约束；支持 `unique(D, f)` 集合唯一性原语；支持分支（`branch`）声明以供 `completeness` 目标使用，分支间互斥由用户显式声明而不由编译器自动插入。
- **形式化定义 / 依据**：`03 §3.5.2`（`distinct` 衍生构造与公理 `AX-Q-INDEP`，全笛卡尔积 vs 单射枚举）、`03 §3.5.3`（退化边界：`k > N` 时 `⋀∅ = ⊤` / `⋁∅ = ⊥`）、`03 §3.9.1`（`A(Q x̄∈D. φ) = N_D^{k'_Q} · A(φ)`）。
- **SMT 编码要点**：`distinct` 展开仅在 `Inj(idx(D), k)` 上枚举（基数 `N·(N−1)···(N−k+1)`，将 `N^k` 降为 `N!/(N−k)!`）；`unique(D,f)` 展开为 `⋀{ s_i.f ≠ s_j.f ∣ i < j }`；分支互斥不在编译期注入，需用户在规范中显式表达。
- **验收要点**：`AC-12`（退化语义）；`distinct` 的因子在预算诊断 JSON 中以 `distinct: true` 标注。
- **错误码**：`E-GROUNDING-BUDGET`（`distinct` 仍超 `G_max` 时）；退出码 3。

#### FR-16 除法全域性义务与线性化重写【v2.1 新增】

- **需求陈述**：`safety` 目标须自动收集策略中所有除/模节点的分母并生成**全域性义务**（分母处处非零）；在义务被独立解除的前提下，含 `Real` 除法的比较可等价线性化重写为无除法形式。
- **形式化定义 / 依据**：`03 §3.11.1`（全函数除法的假证明风险）、`ALG-2 collect_div_obligations`（`03 §3.11.2`）、`TH-4` 线性化重写（`03 §3.11.3`，`LinDiv(a,b,c) ≜ isConst(b) ∨ isConst(c)`）、`命题 3.11.1`（`div`/`mod` 不可线性化，`03 §3.11.4`）。
- **SMT 编码要点**：`safety` 查询为 `(assert Bnd)(assert R_P)(assert (or (= b₁ 0) … (= b_k 0)))(check-sat)`，UNSAT ⇒ PASS，查询本身**不含除法**（`03 §3.11.5`）；`loss / exposure > 1/2` 线性化为 `(exposure > 0 ∧ 2·loss > exposure) ∨ (exposure < 0 ∧ 2·loss < exposure)`，保持 `QF_LIA`；`div`/`mod` 的除数须为常量。
- **验收要点**：`AC-11`；无非零义务时报告须标注 `safety_vacuous: true`（`03 §3.5.3`）。
- **错误码**：`E-NONLINEAR`（`LinDiv` 不成立且未 `--allow-nonlinear`）；退出码 3。

#### FR-17 求解器能力探测与版本锁定【v2.1 新增】

- **需求陈述**：框架启动时对每个后端执行逻辑冒烟探测，以**实测**构建 `SolverCapability` 矩阵；以锁文件 `policylang.lock` 锁定求解器名称、版本与二进制 SHA-256；探测失败即 `Error`，不静默降级。
- **形式化定义 / 依据**：`ALG-3 probe_logic`（`06 §6.4`）、`03 §3.10.3`（`DD-3.2` 能力探测替代硬编码逻辑名）、`00 §0.6`（求解器接口兼容承诺）。
- **SMT 编码要点**：探测查询为极小的 `(set-logic L)` + 平凡 `(check-sat)`，观察求解器是否报 `(error "unsupported logic")`；`UNKNOWN_RISK` 档位在门禁中**只接受 `UnknownReviewRequired`**，禁止输出 `Pass`。
- **验收要点**：`AC-5`；版本/哈希不符时退出码 4。
- **错误码**：`E-SOLVER-VERSION`（名称/版本/哈希与锁文件不符）、`E-SOLVER-MISSING`；退出码 4。

#### FR-18 豁免（Waiver）与人工评审状态机【v2.1 新增】

- **需求陈述**：对失败但被**有效豁免**覆盖的检查，状态置 `Waived`（合并格中高于 `Pass` 但低于 `UnknownReviewRequired`）；豁免必须带责任人、到期日与审批人，过期即失效；`UnknownReviewRequired` 强制进入人工评审状态机。
- **形式化定义 / 依据**：`00 §0.3.2`（豁免定义）、`00 §0.4.1`（`Waived` 状态）、`00 §0.4.2`（合并格）。
- **SMT 编码要点**：无（治理层状态）；豁免记录须进入审计报告，与 `proof_hash` 一并存证。
- **验收要点**：`AC-9`（审计可复算，含豁免链）；过期豁免不得参与合并。
- **错误码**：无新码；非法/过期豁免按 `E-REPORT-IO` 或直接忽略并记入报告。

#### FR-19 机器可读报告与 SARIF 输出【v2.1 新增】

- **需求陈述**：报告以 `spec/report.schema.json`（`schema_version: "1.0"`）为准，并额外支持 SARIF 2.1.0 输出以供代码扫描平台消费；消费方必须容忍未知字段（只增字段承诺）。
- **形式化定义 / 依据**：`00 §0.6`（报告 JSON 兼容承诺）、`07 §7.6`（报告与 SARIF 映射）。
- **SMT 编码要点**：无；`Fail`/`Error` 诊断映射为 SARIF `result.level = error`，`UnknownReviewRequired` 映射为 `warning`。
- **验收要点**：`AC-7` `AC-9`；两种格式字段互不丢失。
- **错误码**：`E-REPORT-IO`；退出码 4。

#### FR-20 多目标批量验证的调度模型【v2.1 新增】

- **需求陈述**：单次运行可声明多个验证目标，调度器须在**有界并发**下批量编排，并对每目标独立执行竞速与交叉验证；任一目标 `Error` 使 `overall_status` 升至 `Error`。默认路径为**一目标一查询文件**（`06 §6.1.2 CO-4`）；增量 `push/pop` 仅用于两处例外：(a) `--incremental-single-solver` 单求解器批量排查；(b) Unsat Core 最小化（`06 §6.9.2`）。`FR-20` 的「批量」指**目标级并行调度**，受三层限流模型约束（`06 §6.6.3`）。
- **形式化定义 / 依据**：`06 §6.9`（批量调度）、`00 §0.4.2`（合并格 join）、`03 §3.9.3`（量级测算表用于容量规划）。
- **SMT 编码要点**：目标间以**独立查询文件**隔离（`06 §6.1.2 CO-4`）；并发度受 `--max-inflight` 限制，避免 `100` 并发请求下峰值内存超 `NFR-3`。
- **验收要点**：`AC-8`；`100` 并发稳定排队，退出码取合并格最大者。
- **错误码**：`E-SOLVER-MISSING`、`E-CROSSVAL-MISMATCH`；退出码 4。

## 5. 非功能需求（NFR-1 ~ NFR-6）

> **绑定纪律**：按 `03 §3.9.3` 与 `03 §3.10.4`，每个性能指标必须绑定 `G_max`（默认 `10⁶`，`--max-groundings`）与 `--timeout` 具体数值，否则指标不可验证。

| ID | 指标要求 | 验证手段 | 绑定参数 | 失败处置 |
|---|---|---|---|---|
| `NFR-1` | **求解延迟**：展开后断言数 = `500` 且 `G ≤ G_max` 时，P99 求解耗时 `< 3 s` | Criterion 基准 + 回归统计（`10 §10.4 BENCH-1`） | `G_max = 10⁶`；`--timeout 3000ms` | 超时判 `UnknownReviewRequired`（退出码 2），不伪装 PASS |
| `NFR-2a` | **检查阶段延迟**（不含展开）：`1000` 行 DSL 编译 `< 200 ms` | 前端基准（`10 §10.4 BENCH-2`） | 不触发展开；`G` 静态计算 | 超时告警；不影响判定正确性 |
| `NFR-2b` | **含展开延迟**：`G = 10⁶` 上界时 `< 500 ms`；`G ∈ (10⁶, 10⁷]` 每 `10⁶` 线性追加 `400 ms` | 展开期基准（`10 §10.4 BENCH-2`） | `G_max = 10⁶`（上界测算），展开须分块 + 惰性 `String` 拼接（`05 §5.7`） | `G > G_max` 即 `E-GROUNDING-BUDGET`（退出码 3） |
| `NFR-3` | **内存与进程隔离**：单次验证峰值内存 `< 512 MB`；竞速结束后子进程残留率 = 0 | 进程树监控 + 故障注入（`10 §10.5`） | `--max-inflight` 并发上限 | 残留进程 `E-SOLVER-MISSING`（退出码 4） |
| `NFR-4` | **并发吞吐**：单机稳定支持 `100` 并发验证请求的排队与调度 | 压力测试（`AC-8`） | 调度并发度 `--max-inflight`，内存预算 `512 MB × inflight` | 超并发上限时排队而非丢弃 |
| `NFR-5` | **UNKNOWN 发生率**：对通过可判定性检查的规则集，UNKNOWN 率 `< 1%` | 回归测试集统计（`10 §10.4`） | `--timeout 3000ms`；`G_max = 10⁶` | 超标时须诚实报告并转人工，不得放宽守卫 |
| `NFR-6` | **审计完整性**：`100%` 验证报告具备可复算 `proof_hash` 与规则行号映射 | 审计合规测试（`AC-9`） | `TH-10` 哈希确定性；`query_hash` 依赖 `DET-1` 字典序 | 复算不一致 `E-REPORT-IO`（退出码 4） |

> **说明**：`NFR-1` 与 `NFR-5` 必须**联合声明**——`G(φ)` 只约束文本/语法规模，不约束求解器内部膨胀（`QF_BV` 位爆破、`QF_LIA` 分支、`QF_SLIA` 自动机乘积，见 `03 §3.9.4`），故 UNKNOWN 率与超时预算不可割裂评估（`03 §3.9.4`）。`NFR-2` 拆分为 `NFR-2a`/`NFR-2b` 的数学理由见 `03 §3.10.4`。

**NFR ↔ G 映射**：`NFR-1` ↔ `G-5`；`NFR-2a`/`NFR-2b` ↔ `G-4`；`NFR-3` ↔ `G-5`；`NFR-4` ↔ `G-7`；`NFR-5` ↔ `G-8`；`NFR-6` ↔ `G-7`。

**容量规划参考（`03 §3.9.3` 量级测算表）**：域规模 `N=100` 时 `∀∀` 规则产生 `10⁴` 子式、`∀∀∀` 达 `10⁶`（触及 `G_max`）；改用 `distinct` 修饰后 `∀∀` 由 `N²` 降为 `N(N−1)`。规划 `N` 与量词嵌套深度时须以该表为准。

## 6. 验收标准（AC-1 ~ AC-12）

> `AC-1`–`AC-7` 沿用上游 v2.0 并**修正其不可实现处**；`AC-8`–`AC-12` 为 v2.1 新增。

| ID | 验收标准 | 修正说明 / 依据 |
|---|---|---|
| `AC-1` | **实体建模与端口冲突反例**：声明 `Service` 实体与 `NoPortConflict` 规则；当存在两个同主机服务端口冲突风险时，`verify invariant` 返回 `Fail`，并输出具体服务标识、宿主机 IP（点分十进制）与冲突端口号。 | **修正**：「服务标识」明确定义为二元组 `(域索引 i, Services[i].id 字段值)`，并附其 `host_ip` 点分十进制与 `port`。依据 `TH-1-C2` 逆映射与 `FR-7`。 |
| `AC-2` | **规则死锁与 Unsat Core 提取**：编写两条互斥规则（规则 A 端口 `> 8000`，规则 B 端口 `< 5000`），`verify consistency` 返回 UNSAT 并通过 Unsat Core 精确指出两条冲突规则名与行号。 | 沿用；`Bnd(S)` 不带 `:named`（`DD-3.1`），核不可被建模假设污染。 |

| `AC-4` | **不可判定构造静态拦截**：声明含两变量相乘 `s.port * s.id > 1000` 的非线性规则，系统在**编译期**拦截并标记 `Unverifiable`，**不进入求解阶段**，CLI 退出码 = `3`（`COMPILE_ERROR`）。 | **修正**：明确退出码 `3` 与错误码 `E-NONLINEAR`（`W8`）；v2.0 未定义编译拦截的退出码（`09 §9.2 B-15`）。 |

| `AC-7` | **CI/CD 门禁闭环**：在 GitHub Actions 中集成 `policylang verify`，提交违反安全不变量的 PR，流水线自动阻断并在 PR 评论/日志打印业务可读反例诊断报告。 | 沿用；门禁脚本须覆盖 `Pass`/`Fail`/`UnknownReviewRequired`/`Waived`/`Error` 五分支（`00 §0.4.4`）。 |
| `AC-8` | **并发压力**：单机 `100` 并发 `policylang verify` 请求下，全部请求在 `--timeout 3000ms` 内返回确定判定或诚实 `UnknownReviewRequired`，退出码取合并格最大者，峰值内存不超预算。 | 新增；`FR-20` / `NFR-4`。 |

| `AC-11` | **除法安全**：对含变量分母的风险比率策略 `verify safety of RiskRatioPolicy`，义务 `exposure ≠ 0` 被正确生成并证明；`loss / exposure > 1/2` 线性化为无除法形式且保持 `QF_LIA`；策略无除法时报告标注 `safety_vacuous: true`。 | 新增；`FR-16` / `TH-4` / `ALG-2`。 |
| `AC-12` | **退化语义**：`N = 1` 的 `forall` 展开为单合取项；`k > N` 的 `distinct` 全称恒真、存在恒假；`unique(D,f)` 在 `N = 1` 时恒真；`matches_all []` 恒真；`N = 0` 或 `Int [min:5, max:3]` 以 `E-EMPTY-CARRIER` 阻断。 | 新增；`03 §3.5.3` / `03 §3.2.6` / `FR-15`。 |
