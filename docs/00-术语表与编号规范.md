## 0.3 术语表（中英对照）

> 首次出现的英文术语在正文中以「中文（English）」形式给出，此后仅用中文。

### 0.3.1 形式化与逻辑

| 中文       | English                       | 定义                                                                 |
| -------- | ----------------------------- | ------------------------------------------------------------------ |
| 排序       | Sort                          | 值的种类（Int / Real / Bool / String / BitVec(n) / Enum），非「类型」以免与实体类型混淆 |
| 标量符号     | Scalar Symbol                 | 展平后的单个 SMT 常量（如 `Services_0_port`）                                 |
| 有界域      | Bounded Domain                | 带显式上下界/长度/位宽的载体，如 `Int [min:1, max:65535]`                         |
| 实例域      | Instance Domain               | `domain D: Set[E] [size:N]`，含 N 个实例，索引集为 `Fin N`                   |
| 展平 / 单态化 | Flattening / Monomorphization | 把 `D_i.f` 映射为独立 SMT 常量的过程                                          |
| 有界量词展开   | Bounded Quantifier Grounding  | 把 `forall`/`exists` 按实例域基数展开为 `⋀`/`⋁`，产生无量词公式                      |
| 可判定性     | Decidability                  | 存在算法对任意输入在有限步内给出 sat/unsat 判定                                      |
| 可判定性静态守卫 | Decidability Guardian         | 编译期遍历 AST，拦截落入不可判定片段（非线性、无界量词、非正则正则）的构造                            |
| 理论       | Theory                        | SMT 的数学背景理论（LIA / LRA / BV / Strings / RegLan…）                    |
| 逻辑档位     | SMT Logic Profile             | 形如 `QF_BVLIA` 的 SMT-LIB `set-logic` 标识                             |
| 反证法编码    | Refutation Encoding           | 断言 `Γ ∧ ¬φ`，以 UNSAT 证明 `Γ ⟹ φ` 的编码范式                               |
| 反例模型     | Counterexample Model          | SAT 时求解器返回的赋值，还原为业务实体视图                                            |
| 最小冲突核    | Minimal Unsat Core            | 不可满足的 `:named` 断言子集，且删去任一元素即变为可满足                                  |
| 冲突核      | Unsat Core                    | 求解器返回的不可满足断言子集（**不保证最小**，需后处理最小化）                                  |
| 保序 / 可靠性 | Soundness                     | 编译变换保持语义（`⟦ground(φ)⟧ = ⟦φ⟧`）                                      |
| 完备性（变换）  | Completeness（transformation）  | 变换不丢失任何解                                                           |
| 划分线性化    | Division Linearization        | 在分母非零义务已解除的前提下，把含除法的比较改写为等价的交叉相乘线性形式                               |
| 全域性义务    | Well-Definedness Obligation   | 要求分母/模数处处非零的验证义务，由 `safety` 目标生成                                   |
| 量词消除     | Quantifier Elimination        | 见「有界量词展开」，本框架特指基于有限实例域的枚举消去                                        |

> **术语纪律**：本框架中「**完备性**」有两个互不相干含义，必须区分：
>
> - `completeness` **验证目标**（FR-3）：策略分支对输入域的全覆盖性（无死区）。
> - 变换的**完备性**（TH-2 侧）：Grounding 不丢失解。  
>   正文中一律写作「completeness 目标」与「变换完备性」。

### 0.3.2 工程与治理

| 中文     | English                 | 定义                                   |
| ------ | ----------------------- | ------------------------------------ |
| 策略即代码  | Policy as Code          | 策略 DSL 与验证目标纳入 Git 版本控制              |
| 语义收敛   | Semantic Refinement     | 新策略约束集是旧策略的子集（`P_new ⟹ P_old`）       |
| 策略包含性  | Subsumption             | 两策略约束集的集合包含关系判别                      |
| 门禁     | Gate                    | CI 中阻断合并的验证检查点                       |
| 溯源自证哈希 | Proof Hash              | 对（规范哈希 ‖ 查询哈希 ‖ 判定结果）的 SHA-256，可离线复算 |
| 运行证明哈希 | Attestation Hash        | 额外覆盖胜出求解器、耗时、宿主信息的法证哈希               |
| 能力探测   | Capability Probing      | 启动时以冒烟查询实测求解器对逻辑档位的支持，构建能力矩阵         |
| 首胜即止   | Winner-Takes-All        | 首个返回确定判定的求解器胜出，其余进程强制回收              |
| 响应流解析  | Response Stream Parsing | 按 SMT-LIB 响应序列（非行）解析求解器 stdout       |
| 模型重放   | Model Replay            | 以独立参考求值器逐位重算模型是否满足全部断言               |
| 诚实阻断   | Honest Blocking         | UNKNOWN 严禁视为 PASS，强制非零退出码 + 人工评审     |
| 豁免     | Waiver                  | 带责任人、到期日与审批人的限时例外，过期即失效              |

## 0.4 状态、退出码与合并格（Lattice）

### 0.4.1 单项检查状态 `CheckStatus`

| 值                       | 语义                      | 终端退出码贡献  |
| ----------------------- | ----------------------- | -------- |
| `Pass`                  | 数学命题成立（或该目标下无义务）        | 0        |
| `Fail`                  | 找到反例 / 冲突核              | 1        |
| `UnknownReviewRequired` | 求解器超时或返回 unknown        | 2        |
| `Waived`                | 失败但被有效豁免（未过期）覆盖         | 0（报告中可见） |
| `Error`                 | 编译阻断 / 求解器不可用 / 交叉验证不一致 | 4        |

### 0.4.2 合并规则（严格偏序）

```
Error  ⊐  Fail  ⊐  UnknownReviewRequired  ⊐  Waived  ⊐  Pass
```

`overall_status = join{ status(c) | c ∈ checks }`（取偏序最大者）。

### 0.4.3 CLI 退出码

| 码   | 名称                      | 触发条件                                       |
| --- | ----------------------- | ------------------------------------------ |
| `0` | PASS                    | `overall_status ∈ {Pass, Waived}`          |
| `1` | VERIFICATION_FAILED     | `overall_status = Fail`                    |
| `2` | UNKNOWN_REVIEW_REQUIRED | `overall_status = UnknownReviewRequired`   |
| `3` | COMPILE_ERROR           | 解析 / 合式性 / 可判定性守卫阻断（含 `E-UNVERIFIABLE` 家族） |
| `4` | INTERNAL_ERROR          | 求解器缺失或版本不符 / IO 失败 / 交叉验证不一致 / 报告落盘失败      |

> **与原 v2.0 的差异**：v2.0 仅定义 0/1/2，导致 AC-4 的「编译期拦截」与求解器缺失场景无码可返（见 `09 §9.2 B-15`）。本规范冻结 5 码制，**3/4 为新增**。

### 0.4.4 `overall_status` 的 JSON 序列化

沿用 v2.0 的 Rust 枚举默认序列化风格（无额外 `rename`）：

```
"Pass" | "Fail" | "UnknownReviewRequired" | "Waived" | "Error"
```

CI 门禁脚本必须显式覆盖全部 5 个分支（v2.0 的 3 分支脚本会把 `Error` 误判为 `Fail`，见 `09 §9.2 B-16`）。

## 0.5 占位符（`TXT` / `TXT +N`）处理说明

上游 v2.0 文档以 `TXT`、`TXT + 1`、`TXT + 2`、`TXT + 4` 等标记**跨文档引用**（原平台外部文档链接或脚注标记），并伴随大量被截断的表格单元格（表格行被拆成「值行 + `TXT` 行」两行）。

**本次处理规则（已全量执行）**：

| 原形态                                                          | 处理方式                                      |
| ------------------------------------------------------------ | ----------------------------------------- |
| 单元格内容 + 独立 `TXT (+N)` 行                                      | 判定为「同一单元格的值 + 外部引用计数」，**合并为单行单元格**，丢弃引用标记 |
| 表格被拆成「值行 / `TXT` 行」交替                                        | 重新装配为规范 Markdown 表格，`\|` 转义               |
| `+1`/`+2`/`+4` 计数                                            | 视为**同一单元格被多个文档引用**的计数，对内容无影响，丢弃           |
| 被转义破坏的数学式（如 `∀i<j,s i .field =s j .field`、`⋀ i=1 N P(x i )`） | 按上下文还原为标准数学记号                             |
| `└──marketing-coupon.pl`（缺空格）                                | 修正为 `└── marketing-coupon.pl`             |
| `policylang-Check`（大小写不规范）                                   | 修正为 `policylang-check`                    |

> **无内容丢失**：上游文档的每一条陈述均已在 01–12 中找到归属位置；无法归属者列入 `09 §9.5 开放问题`。此外，上游未闭合的设计缺口由本文件集**补全**而非删除，补全清单见 `09`。
