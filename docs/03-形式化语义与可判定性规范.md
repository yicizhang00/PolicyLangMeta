## 3.1 元层记号与约定

| 记号 | 含义 |
|---|---|
| `ℕ, ℤ, ℚ, ℝ` | 自然数（含 0）/ 整数 / 有理数 / 实数 |
| `𝔹` | `{⊤, ⊥}`（真、假） |
| `Σ` | Unicode 码点全集；`Σ*` 为码点序列（字串）集合；`\|w\|` 为字串长度（码点数） |
| `Fin n` | `{0, 1, …, n−1}` |
| `x̄` | 变量组 `x₁, …, x_k` |
| `⋀{φᵢ}` / `⋁{φᵢ}` | 有限合取 / 有限析取；**约定 `⋀∅ = ⊤`，`⋁∅ = ⊥`** |
| `ρ[x ↦ v]` | 赋值 `ρ` 在 `x` 上更新为 `v`（其余不变） |
| `⟦e⟧ρ` | 表达式 `e` 在赋值 `ρ` 下的取值 |
| `ρ ⊨ φ` | `⟦φ⟧ρ = ⊤` |
| `⊨ φ` | 对一切合法 `ρ` 有 `ρ ⊨ φ`（亦写作 `∀m ∈ M. φ(m)`） |
| `≡` | 语义等价（两侧在相同赋值下取值相同） |
| `&` | 位串按位与（`bvand`）；`p ∧ q` 保留给逻辑合取 |
| `#x…` | 十六进制位串字面量 |
| `div` / `mod` | SMT-LIB 整数理论的**全函数**整除与取模（floor 语义），非数学除法 |
| `/` | SMT-LIB 实数理论的**全函数**除法，`ℚ` 上精确 |

> **约定 3.1.1（大写 / 小写分隔）**：本文以大写下标标识**集合**（`Flat`、`GVar`、`M`），小写标识**元素与函数**，以 `QNest(·)` 标识量词嵌套序列。

## 3.2 排序签名与语义模型

### 3.2.1 排序（Sort）

```
σ ::= Int | Real | Bool | Str | BV(n)      (n ∈ ℕ⁺)
    | Enum(E)                              (E = {e₁,…,e_k}, k ≥ 1)
```

> **术语纪律（【补全 A-18】）**：`Enum` 是**排序**，不是实体类型。实体的类型由「记录模式（record schema）」给出，见 §3.2.4。

### 3.2.2 语义载体（Carrier）

每个排序 `σ` 配一个全域载体 `D_σ`；范围约束 `c` 把载体收缩为**受限载体** `D_{σ,c}`：

| `σ` | 全域载体 `D_σ` | 范围约束 `c` 的形态 | 受限载体 `D_{σ,c}` |
|---|---|---|---|
| `Int` | `ℤ` | `[min: a, max: b]`，`a,b ∈ ℤ` | `{ z ∈ ℤ ∣ a ≤ z ≤ b }` |
| `Real` | `ℝ` | `[min: a, max: b]`，`a,b ∈ ℚ` | `{ x ∈ ℝ ∣ a ≤ x ≤ b }` |
| `Bool` | `𝔹` | 无（天然有界） | `𝔹` |
| `Str` | `Σ*` | `[length: l..u]`，`0 ≤ l ≤ u ∈ ℕ` | `{ w ∈ Σ* ∣ l ≤ \|w\| ≤ u }` |
| `BV(n)` | `{0,…,2ⁿ−1}` | 无（位宽即界） | `{0,…,2ⁿ−1}` |
| `Enum(E)` | `E` | 无（枚举即界） | `E` |

### 3.2.3 规范化约定（Normative）

- **N-1**：`Real` 的语义载体为 `ℚ`（SMT-LIB 实数理论以**精确有理数**为模型）；`D_Real` 中的闭区间端点必须可表示为有理数，字面量不得为无理数。跨平台复算时一律以 `ℚ` 的 `num/den` 表示，**严禁**使用 IEEE-754 浮点参与模型重放（见 `06 §6.7`）。
- **N-2**：`String` 的长度以**码点**计数（与 `str.len` 一致）。
- **N-3**：`BV(n)` 为**无符号位串**，唯一表示；`BV(n)` 上的比较一律使用无符号算子 `bvult` / `bvule` / `bvugt` / `bvuge`，**不存在符号歧义**。
- **N-4**：**严禁排序隐式提升**。`Int` 与 `Real` 混用必须显式 `to_real`；`BV(n)` 与 `Int` 混用必须显式 `bv2int`/`int2bv` 且**编译期拒绝**（`bv2int` 会使查询落入非线性片段）。**【补全 A-18】**

> **重要修正（【补全 A-2】）**：上游 v2.0 反复表述「强制有限有界域 ⇒ 可判定性」。该因果关系**不成立**：
> - `Real` 区间有界但**不可数**，`Str` 长度有界但**字母表无限**——二者都不是有限域；
> - 可判定性的真正来源是 **① 量词消除（§3.7）+ ② 仅使用可判定理论片段（§3.11）**；
> - **有界性的真实作用**是三个工程目标：(a) 保证量词可枚举展开，(b) 保证反例模型可被有限、可复算地序列化，(c) 保证模型重放可在有限时间内按精确算术完成。
>
> 本文此后一律以「有界 + 量词消除 + 可判定片段」三元组表述，不再使用「有限域」这一过强措辞。

### 3.2.4 记录模式、实例域与展平

**定义 3.2.1（记录模式 Record Schema）** 实体声明 `entity E { … }` 定义一个有序字段序列

```
Schema(E) = ⟨ (f₁, σ₁, c₁), …, (f_m, σ_m, c_m) ⟩
```

**定义 3.2.2（实例域 Instance Domain）** `domain D : Set[E] [size: N]` 定义一个**索引集** `idx(D) = Fin N`（`N ≥ 1`，见 W3）。`D` 的每个索引 `i` 对应一个实例，其字段 `f` 的取值是一个独立的标量。

**定义 3.2.3（展平 Flat）** 展平映射

```
flat : { (D, i, f) ∣ D ∈ Domains, i ∈ idx(D), f ∈ fields(entity(D)) } → Sym
flat(D, i, f) = ⟨D⟩_⟨i⟩_⟨f⟩            —— 注入（injective）具名常量符号
```

**符号命名规范**（【补全 A-7；上游对应的实现调用点见 `09 §9.2 B-8`】）

```
scalar_symbol(D, i, f) = "PL_" + escape(D) + "_" + dec(i) + "_" + escape(f)
escape(s) = 把 s 中每个非 [A-Za-z0-9_] 字符替换为 "_u" + 4 位十六进制
```

- 强制前缀 `PL_` 规避与理论保留字（`div`、`mod`、`abs`、`to_real`…）及求解器内建符号冲突；
- 索引以**十进制**书写，不使用下划线与字段名混淆；
- `escape` 保证**单射**，消除「字段名含下划线」导致的命名碰撞（上游 v2.0 的 `format!("{}_{}", prefix, field)` 存在碰撞风险）。

**定义 3.2.4（全局变量集 `GVar`）** `var v : σ [c]` 声明一个全局常量符号 `v`。

### 3.2.5 状态空间与边界断言

**定义 3.2.5（状态空间）**

```
M ≜  ∏_{(D,i,f) ∈ Flat}  D_{σ(f), c(f)}   ×   ∏_{v ∈ GVar}  D_{σ(v), c(v)}
```

**定义 3.2.6（边界断言 `Bnd`）** 规范 `S` 诱导的边界断言为其受限载体之特征谓词的全合取：

```
Bnd(S) ≜  ⋀_{(D,i,f) ∈ Flat}  bound_{σ(f),c(f)}(scalar_symbol(D,i,f))
        ∧ ⋀_{v ∈ GVar}        bound_{σ(v),c(v)}(v)

bound_{Int,[a,b]}(x)      ≜  (and (>= x a) (<= x b))
bound_{Real,[a,b]}(x)     ≜  (and (>= x a) (<= x b))
bound_{Bool,_}(x)         ≜  true
bound_{Str,l..u}(x)       ≜  (and (>= (str.len x) l) (<= (str.len x) u))
bound_{BV(n),_}(x)        ≜  true          —— 位宽由排序强制
bound_{Enum(E),_}(x)      ≜  (or (= x v₁) … (= x v_k))
```

### 3.2.6 设计决策 DD-3.1（`Bnd` 不带 `:named` 标签）

> **关键设计决策 DD-3.1**：`Bnd(S)` 在生成的 SMT-LIB2 中**不带 `:named` 标签**。理由：范围约束是**建模假设**而非「可被发现的冲突」，不应污染 Unsat Core。反之，若 `Bnd(S)` 本身不可满足（如 `Int [min:5, max:3]`），Unsat Core 将为空——此时框架必须报告 `E-EMPTY-CARRIER` 而非「空冲突核」（见 `06 §6.2.4` 的 `Bnd` 可满足性预检与 `06 §6.9.4`）。

**性质 3.2.1** `Bnd(S)` 恒为**无量词**且**仅含理论原子**，因此不引入不可判定构造。

## 3.3 合式性判定（Well-Formedness）

**定义 3.3.1（合式）** 规范 `S` 合式，当且仅当 `W1–W12` 全部成立。违反任一条件即在**编译期**以对应 `E-*` 码阻断，`overall_status = Error`、CLI 退出码 `3`。

| 编号 | 条件 | 违反时错误码 |
|---|---|---|
| `W1` | 每个实体字段与全局变量的**排序声明完整**：`BitVec` 必须给出位宽 `n ≥ 1`；`Enum` 必须给出 `k ≥ 1` 个**互异**成员名 | `E-BAD-SORT` |
| `W2` | 每个 `Int`/`Real` 字段与变量**必须**有 `[min:a, max:b]`；每个 `Str` **必须**有 `[length: l..u]` | `E-MISSING-RANGE` |
| `W3` | 范围约束自洽：`a ≤ b`（`Int`/`Real`）；`0 ≤ l ≤ u`（`Str`）；`size: N` 且 `N ≥ 1` | `E-EMPTY-CARRIER` |
| `W4` | `domain D : Set[E] [size:N]` 中 `E` 已声明；同一 `D` 名不得重复声明 | `E-UNKNOWN-ENTITY` / `E-DUP-SYMBOL` |
| `W5` | 每个 `field_access x.f` 的 `x` 是**当前量化式引入的绑定变量**，且 `f ∈ fields(entity(domain(x)))` | `E-UNBOUND-INSTANCE` / `E-UNKNOWN-FIELD` |
| `W6` | 每个裸标识符 `v` 要么是**量化绑定变量**，要么是**已声明的全局变量**；不存在自由变量 | `E-UNBOUND-VAR` |
| `W7` | 占用排序一致：比较与算式两侧排序相同；**无隐式提升**（N-4） | `E-SORT-MISMATCH` |
| `W8` | **线性性**：不存在两个**非常量**操作数的 `*`；不存在**非常量**除数的 `/`、`div`、`mod`（见 §3.12） | `E-NONLINEAR` |
| `W9` | **正则子语言**：所有 `matches_all` 中的模式属于 `R_sub`（§3.14） | `E-REGEX-NONREGULAR` |
| `W10` | `in_cidr(e, c)` 的 `c` 为合法 CIDR 字面量且地址族（IPv4/IPv6）与 `e` 的位宽匹配 | `E-CIDR-WIDTH` / `E-CIDR-SYNTAX` |
| `W11` | **Grounding 预算**：`G(φ) ≤ G_max`（默认 `10⁶`，§3.10） | `E-GROUNDING-BUDGET` |
| `W12` | 每个 `verify` 目标的被引用符号（策略名 / 不变量名 / 域 / `branch` 集）已声明；被验证策略**非空** | `E-UNKNOWN-TARGET` / `E-EMPTYPOLICY` |

### 3.3.1 声明顺序与可见性（【补全 A-17】）

**规则 D-1（域拓扑序）** 规范 `S` 的声明集合构成依赖图 `S → E`（域依赖实体）、`D → E`（域依赖实体）、`V → {S, V}`（验证目标依赖策略/不变量）。编译器执行**拓扑排序**；存在环即 `E-CYCLIC-DECL`。因此**声明书写顺序不受约束**，允许前向引用。

**规则 D-2（作用域）**
- 量化绑定变量 `x` 的作用域为**其量词体**；
- 全局变量 `v` 在**全部策略规则、不变量、分支**中可见，包括量化体内部；
- 量化绑定变量**遮蔽**同名全局变量（词法遮蔽，编译期给出 `W-SHADOW` 警告，非错误）；
- **禁止**在量化体内引用另一个域的实例（如 `foralls∈Services: forall t∈Databases: s.db_host == t.host` 应通过 `Databases` 域声明），因为跨域字段名解析歧义无法静态消解。违反即 `E-CROSS-DOMAIN-REF`。

## 3.4 类型系统

**类型环境** `Γ` 为偏函数 `Γ : (BindVar ∪ GVar ∪ (BindVar × Field)) ⇀ Sort`。

**判断形式**：`Γ ⊢ e : σ`（表达式）与 `Γ ⊢ φ : Bool`（公式；公式即排序为 `Bool` 的表达式）。

### 3.4.1 表达式规则

```
────────────────────────  (T-GVAR)         v ∈ GVar = dom(Γ)
Γ ⊢ v : Γ(v)

────────────────────────  (T-BVAR)         x ∈ BindVar
Γ ⊢ x : DomSort(x)                          —— 仅当你出现在 field_access 位置，见 T-FIELD

────────────────────────  (T-FIELD)        x ∈ BindVar, f ∈ fields(entity(domain(x)))
Γ ⊢ x.f : σ_f

───  (T-INTLIT)      ───  (T-REALLIT)      ───  (T-BOOLLIT)      ───  (T-STRLIT)
Γ ⊢ n : Int          Γ ⊢ q : Real          Γ ⊢ b : Bool         Γ ⊢ w : Str

──────────────  (T-NEG)   Γ ⊢ e : Int ∨ Γ ⊢ e : Real
Γ ⊢ (- e) : Γ(e).sort

Γ ⊢ a : σ    Γ ⊢ b : σ    σ ∈ {Int, Real}    Lin(a, b)          (T-ADD)
────────────────────────────────────────────────────────────
Γ ⊢ (a + b) : σ

Γ ⊢ a : σ    Γ ⊢ b : σ    σ ∈ {Int, Real}    Lin(a, b)          (T-SUB)
────────────────────────────────────────────────────────────
Γ ⊢ (a - b) : σ

Γ ⊢ a : σ    Γ ⊢ b : σ    σ ∈ {Int, Real}    LinMul(a, b)       (T-MUL)
────────────────────────────────────────────────────────────
Γ ⊢ (a * b) : σ

Γ ⊢ a : Real   Γ ⊢ b : Real   isConst(b)   ⟦b⟧ ≠ 0             (T-RDIV-1)
──────────────────────────────────────────────────────────────
Γ ⊢ (a / b) : Real

Γ ⊢ a : Real   Γ ⊢ b : Real   ¬isConst(b)   optin(NonLinear)   (T-RDIV-2 → QF_NRA)
──────────────────────────────────────────────────────────────
Γ ⊢ (a / b) : Real                      —— 默认拒绝，仅 --allow-nonlinear 放行

Γ ⊢ a : Int   Γ ⊢ b : Int   isConst(b)   ⟦b⟧ ≠ 0               (T-IDIV)
────────────────────────────────────────────────────────────
Γ ⊢ (div a b) : Int          （mod 同形）

Γ ⊢ e : σ   σ = BV(n)                                          (T-BV-OPS)
────────────────────────────────────────────────────────────
Γ ⊢ (bvnot|bvand|bvor|bvxor|bvadd|bvsub|bvmul|bvshl|bvlshr e… ) : BV(n)

Γ ⊢ a : Int    (a ∈ [0, 2ⁿ−1])                                 (T-INT2BV)
────────────────────────────────────────────────────────────
Γ ⊢ (int2bv(n) a) : BV(n)

Γ ⊢ e : Str                                                    (T-STRLEN)
────────────────────────────────────────────────────────────
Γ ⊢ (str.len e) : Int
```

**线性性侧条件**

```
Lin(e)        ≜ e 的语法树中每个 * 节点至少有一个操作数为编译期常量
LinMul(a, b)  ≜ isConst(a) ∨ isConst(b)
isConst(e)    ≜ e 中不含任何 GVar、BindVar、field_access（即纯字面量表达式）
```

> **重要修正（【补全 A-8 / C-5】）**：上游 `LogicProfile::check_expr` 的守卫写作
> `if !left.is_constant() && !right.is_constant()`——该条件**只覆盖 `*` 与 `div` 两侧皆非常量的情形，漏掉 `2 / x`、`2 div x`、`2 mod x`（左侧常量、右侧变量）这一真正非线性且不可判定的构造**。
> 本规范把线性性拆为**两个独立侧条件**：
> - `LinMul(a,b) ≜ isConst(a) ∨ isConst(b)`（乘法：单侧常量即可判）
> - **除法侧条件独立**：`div`/`mod` **要求除数为常量**（`isConst(b) ∧ ⟦b⟧ ≠ 0`）；`/` 默认同样要求常量除数，否则转入 `QF_NRA` 并须显式 `opt-in`。
>
> 这一修正使「G-4 100% 拦截非线性」在数学上真正成立。

### 3.4.2 公式规则

```
Γ ⊢ e : Bool                                                  (T-BOOL-ATOM)
────────────────────────────────────────
Γ ⊢ e : Bool

Γ ⊢ a : σ   Γ ⊢ b : σ   σ ∈ {Int, Real, BV(n)}   R ∈ {=, ≠, <, ≤, >, ≥}   (T-CMP-NUM)
──────────────────────────────────────────────────────────────────────────
Γ ⊢ (a R b) : Bool

Γ ⊢ a : Str   Γ ⊢ b : Str                                     (T-CMP-STR)
──────────────────────────────────────────
Γ ⊢ (a = b) : Bool   Γ ⊢ (a ≠ b) : Bool
Γ ⊢ (str.< a b) : Bool   Γ ⊢ (str.<= a b) : Bool      —— 字典序，可判定

Γ ⊢ a : Enum(E)   Γ ⊢ b : Enum(E)   R ∈ {=, ≠}                (T-CMP-ENUM)
─────────────────────────────────────────────────────────────
Γ ⊢ (a R b) : Bool

Γ ⊢ x : σ   Γ ⊢ a : σ   Γ ⊢ b : σ   σ ∈ {Int, Real}            (T-INRANGE)
───────────────────────────────────────────────────────────
Γ ⊢ (x in [a..b]) : Bool          ≡  (and (<= a x) (<= x b))

Γ ⊢ d : Domain   f ∈ fields(entity(d))                        (T-UNIQUE)
───────────────────────────────────────────────────
Γ ⊢ (unique(d, f)) : Bool

Γ ⊢ e : Str   ∀r ∈ r̄. r ∈ R_sub                                (T-MATCHES)
───────────────────────────────────────────────────
Γ ⊢ (e matches_all [r̄]) : Bool

Γ ⊢ e : BV(n)   fam(c) = fam(n)   p(c) ∈ [0, n]                (T-ICIDR)
─────────────────────────────────────────────────
Γ ⊢ (in_cidr(e, c)) : Bool

Γ ⊢ φ : Bool  Γ ⊢ ψ : Bool                                    (T-BOOL-OPS)
──────────────────────────────────────
Γ ⊢ (and φ ψ) : Bool   (or …)   (not φ)   (implies φ ψ)   (iff φ ψ)

x̄ ∩ dom(Γ) = ∅   k ≥ 1   每个 xⱼ 绑定到域 D    Γ, x̄ : D, D, …⊢ φ : Bool   (T-QUANT)
──────────────────────────────────────────────────────────────────────────
Γ ⊢ ((forall|exists) x̄ in D: φ) : Bool
```

### 3.4.3 运算符优先级（规范）

```
formula  ::= iff        （最低结合）
iff      ::= implies ("iff" implies)*            —— 右结合
implies  ::= or ("implies" implies)?             —— 右结合
or       ::= and ("or" and)*                     —— 左结合
and      ::= not ("and" not)*                    —— 左结合
not      ::= "not" not | primary
primary  ::= quantifier | matches_all | in_cidr | in_range | unique
           | bool_atom | "(" formula ")"
```

> **【补全 B-3 / C-2】**：上游文法 `spec/grammar.pest` 的 `formula = { f_implies }` **完全没有 `iff` 产生式**，而 §4.1 原语表却把 `iff` 列为「逻辑组合子」。本规范补入 `f_iff` 并定为最低优先级（数学上 `φ iff ψ ≡ (φ ⟹ ψ) ∧ (ψ ⟹ φ)`）。
>
> **【补全 B-2，上游文法自相矛盾】**：上游 `f_primary` 仅有 `predicate`（形如 `expr cmp_op expr`），**没有布尔原子产生式**，因此上游 §4.1/§FR-2 自己的示例
> ```
> (s1.uses_db and s2.uses_db) implies (…)
> ```
> **无法被上游自己的文法解析**（`s1.uses_db` 是 `field_access`，而 `field_access` 只出现在 `factor` 里，永远无法上升为 `formula`）。
> 本规范新增 `bool_atom = { expr }` 产生式，并以类型检查 `Γ ⊢ e : Bool`（`T-BOOL-ATOM`）作为语义闸门。

## 3.5 指称语义

赋值 `ρ ∈ M`。`⟦·⟧ : (Term ∪ Formula) × M → (⋃D) ∪ 𝔹`。

### 3.5.1 项

```
⟦c⟧ρ                    = 字面量 c 的自然解释（Int→ℤ，Real→ℚ，Bool→𝔹，Str→w，BV(n)→{0..2ⁿ−1}）
⟦v⟧ρ                    = ρ(v)                                    v ∈ GVar
⟦x.f⟧ρ                  = ρ(flat(domain(x), ρ(x), f))               —— 见 T-ENV，量化变量在 ρ 中已绑定到索引
⟦(a + b)⟧ρ              = ⟦a⟧ρ + ⟦b⟧ρ
⟦(a - b)⟧ρ              = ⟦a⟧ρ − ⟦b⟧ρ
⟦(a * b)⟧ρ              = ⟦a⟧ρ × ⟦b⟧ρ
⟦(a / b)⟧ρ              = ⟦a⟧ρ / ⟦b⟧ρ      （b ≠ 0；b = 0 时取理论全函数的未指定值，见 §3.12 注记）
⟦(div a b)⟧ρ            = floor_div(⟦a⟧ρ, ⟦b⟧ρ)
⟦(mod a b)⟧ρ            = floor_mod(⟦a⟧ρ, ⟦b⟧ρ)
⟦(bvand a b)⟧ρ          = ⟦a⟧ρ & ⟦b⟧ρ      （位宽 n 下按位与）
⟦(str.len e)⟧ρ          = |⟦e⟧ρ|
```

### 3.5.2 公式

```
⟦true⟧ρ                 = ⊤                       ⟦false⟧ρ = ⊥
⟦(not φ)⟧ρ              = ¬ ⟦φ⟧ρ
⟦(and φ ψ)⟧ρ            = ⟦φ⟧ρ ∧ ⟦ψ⟧ρ            （n 元：⋀）
⟦(or  φ ψ)⟧ρ            = ⟦φ⟧ρ ∨ ⟦ψ⟧ρ            （n 元：⋁）
⟦(implies φ ψ)⟧ρ        = ⟦φ⟧ρ ⟹ ⟦ψ⟧ρ
⟦(iff φ ψ)⟧ρ            = ⟦φ⟧ρ ⟺ ⟦ψ⟧ρ
⟦(a R b)⟧ρ              = ⟦a⟧ρ R ⟦b⟧ρ             （R 为对应排序的关系统）
⟦(x in [a..b])⟧ρ        = ⟦a⟧ρ ≤ ⟦x⟧ρ ≤ ⟦b⟧ρ
⟦(unique(D,f))⟧ρ        = ⋀{ ρ(flat(D,i,f)) ≠ ρ(flat(D,j,f))  ∣ i, j ∈ idx(D), i < j }
⟦(e matches_all[r̄])⟧ρ   = ⟦e⟧ρ ∈ ⋂{ L(r) ∣ r ∈ r̄ }
⟦(in_cidr(e,c))⟧ρ       = ( ⟦e⟧ρ & mask(c) ) = net(c)
```

**量词（核心定义）**

```
⟦(forall x̄ ∈ D: φ)⟧ρ    = ⋀{ ⟦φ⟧  ρ[ x₁↦i₁, …, x_k↦i_k ]  ∣  (i₁,…,i_k) ∈ idx(D)^k }
⟦(exists x̄ ∈ D: φ)⟧ρ    = ⋁{ ⟦φ⟧  ρ[ x₁↦i₁, …, x_k↦i_k ]  ∣  (i₁,…,i_k) ∈ idx(D)^k }
```

> **公理 AX-Q-INDEP（【补全 A-4】）** 上述定义采用**全笛卡尔积**，即 `forall x₁, x₂ ∈ D` **允许 `x₁` 与 `x₂` 取同一索引**（对角项 `(i,i)` 被枚举）。这正是上游 `NoPortConflict` 规则需要显式写 `s1.id != s2.id` 守卫的原因。
>
> **衍生构造 `distinct`（新增，FR-15）** 语法 `forall x̄ in D distinct: φ`，其语义为**单射枚举**：
> ```
> ⟦(forall x̄ ∈ D distinct: φ)⟧ρ = ⋀{ ⟦φ⟧ρ[x̄↦ī] ∣ ī ∈ Inj(idx(D), k) }
> Inj(S,k) ≜ { ī ∈ S^k ∣ i₁,…,i_k 两两互异 }              —— 基数 = N·(N−1)···(N−k+1)
> ```
> 二者**语义不等价**（`distinct` 版本更强），因此**必须显式声明**，不得由编译器自动插入。
>
> **上游 v2.0 未定义此公理**，导致「`forall s1,s2` 是否含对角项」不可判——这是一处**语义空洞**（`09 §9.1 A-4`）。

### 3.5.3 退化边界语义（【补全 A-5】）

| 情形 | 语义 |
|---|---|
| `size: N`，`N = 1`，`forall x∈D: φ` | `⟦φ⟧ρ[x↦0]`（单合取项） |
| `forall x̄ ∈ D distinct`，`k > N` | `Inj(idx(D), k) = ∅` ⇒ `⋀∅ = ⊤`（**恒真**） |
| `exists x̄ ∈ D distinct`，`k > N` | `⋁∅ = ⊥`（**恒假**） |
| `unique(D, f)`，`N = 1` | `⋀∅ = ⊤`（**恒真**） |
| `matches_all []`（空模式表） | `⋂∅ = Σ*` ⇒ **恒真** |
| `safety` 目标的策略中**无任何除法节点** | 义务集为空 ⇒ `⋀∅ = ⊤` ⇒ **恒真**（报告须标注 `safety_vacuous: true`） |
| 被验证策略 **0 条规则** | `W12` 阻断（`E-EMPTYPOLICY`）。若放行，`consistency` 恒 SAT、`refines` 恒 FAIL，语义退化，故直接拒绝 |
| 实体声明但**无对应域** | 允许；`W5` 使得任何 `field_access` 都无法引用其实例 ⇒ 该实体实际不可用（编译期给 `W-UNUSED-ENTITY`） |

> **`size: N ≥ 1` 的理由（W3）**：`N = 0` 时 `flat` 像为空 ⇒ 所有域量化恒真/恒假，`consistency` 退化为仅检查全局变量约束，用户意图几乎必然被误解。**禁止 `N = 0`**，需要「可选实体」语义时用 `Bool exists_flag` 字段 + 守卫表达。

## 3.6 有界量词展开算法 `ALG-1 ground`

### 3.6.1 定义

```
ALG-1  ground(φ, Σ, Δ) → QFFormula

输入  φ : Formula               —— 已通过 W1–W12 的合式公式
      Σ : Env                   —— 绑定变量 → 实例前缀（如 s₁ ↦ (Services, 0)）
      Δ : DomainTable           —— 域名 → (实体名, size)
输出  无量词公式
不变量 INV-G：输出中不含 Forall/Exists 节点

  ground( Forall(x̄, D, φ), Σ, Δ ) :
      N    ← Δ(D).size ;  k ← |x̄| ;  k' ← 在 φ 中实际出现的 x̄ 个数
      if k' = 0:                       return ground(φ, Σ, Δ)          // 死变量剪枝（§3.10）
      tuples ← (k' = k) ? idx(D)^k  : idx(D)^{k'}                       // 见 ALG-1-P 部分出现规则
      acc  ← []
      for ī in lexicographic_order(tuples):                             // 确定性顺序
          if distinct 修饰: if ī 有重复: continue
          acc.push( ground(φ, Σ[x̄↦(D, ī)], Δ) )
      return And(acc)                       // acc = ∅ ⇒ And(∅) ≡ true

  ground( Exists(x̄, D, φ), Σ, Δ ) : 同上，返回 Or(acc)     // acc = ∅ ⇒ Or(∅) ≡ false

  ground( And(φ̄), Σ, Δ )    → And( map:ground(·,Σ,Δ) )
  ground( Or(φ̄), Σ, Δ )     → Or ( map:ground(·,Σ,Δ) )
  ground( Not(φ), Σ, Δ )    → Not( ground(φ,Σ,Δ) )
  ground( Implies(φ,ψ),Σ,Δ) → Implies( ground(φ,Σ,Δ), ground(ψ,Σ,Δ) )
  ground( Iff(φ,ψ), Σ, Δ )  → Iff( ground(φ,Σ,Δ), ground(ψ,Σ,Δ) )
  ground( atom, Σ, Δ )      → atom[ x.f ↦ flat(domain(x), Σ(x), f) ]     // 纯重命名
```

**关键实现要求（对应 `09 §9.2 B-8/B-9`）**

| 编号 | 要求 |
|---|---|
| `INV-G` | 输出中不含量词节点（由 `TH-2` 保证） |
| `DET-1` | 枚举顺序为 `Fin N` 元组的**字典序**，保证 `ground` 是**纯函数**，从而 `query_hash` 可复算（`TH-10`） |
| `DET-2` | `And`/`Or` 子项按枚举顺序保序，不做交换律规范化（保持与源码 `:named` 的稳定对应） |
| `FOLD-1` | 展开后对**常量真值**做局部折叠：`and(…, true, …)` 消去 `true`；若出现 `false`，该 `And` 整体化为 `false` 并**保留**被消去子式的 `:named` 影子记录（供诊断） |
| `FOLD-2` | 相邻**完全同构**的子式去重（`α-等价去重`），把 `∀s₁,s₂. φ` 的对称项从 N² 降到 N(N+1)/2（仅当 `φ` 在交换 `s₁,s₂` 下不变时） |
| `CSE-1` | 公共子式（尤其 `str.in_re` 项）提取为 SMT-LIB `(let ((t …)) …)`，控制文本规模 |
| `ALG-1-P` | 部分出现：若 `x̄ = (x₁,…,x_k)` 中仅 `x₁,…,x_{k'}` 实际出现，则**只枚举 `idx(D)^{k'}`**；未出现的变量在 `Σ` 中绑定为 `(D, 0)`（其 `field_access` 不存在，不影响语义） |

> **【补全 B-6】**：上游 `ground_formula` 直接 `map` 到 `And`/`Or`，**没有死变量剪枝、没有去重、没有常量折叠、没有 CSE**，且未定义 `cartesian_indices` 的枚举顺序。在 `size: 100` 的双变量规则下将产生 `10⁴` 个子式并全部展开，`∀∀∀` 达 `10⁶`。本规范补齐全部五项优化，并把未优化规模作为**预算判定上界**保留（§3.10）。

### 3.6.2 绑定环境的重命名一致性

`Σ` 建立 `绑定变量 ↦ (域名, 索引)`。项层重命名由 `ground_expr` 完成：

```
ground_expr(x.f, Σ)  = Var( scalar_symbol(Σ(x).domain, Σ(x).index, f) )
else                  = 结构递归
```

> **【补全 B-9】**：上游 `ground_expr` 生成 `"Services_0_host_ip"` 字符串并交由**未实现的** `emit_flattened_declarations` 声明；本规范以 §3.2.4 的 `scalar_symbol` 单射编码固定命名，并要求 `05 §5.6` 的声明发射器**严格复用同一函数**（单一实现，避免两处命名漂移）。Rust 侧签名：

```rust

pub fn domain_instance(domain: &str, index: usize) -> String; // "PL_<D>_<i>"
```

## 3.7 定理 TH-1：Grounding 保持定理

> **定理 TH-1（Grounding Preservation）**
> 设 `φ` 合式（W1–W12 成立），`ρ ∈ M` 为任意赋值。则
> ```
> ⟦ ground(φ, Σ, Δ) ⟧ρ  =  ⟦ φ ⟧ρ
> ```

**证明**

对 `φ` 的结构归纳。记 `Σ = Σ₀` 初值（空环境）。

- **原子情形**（比较式、`in [a..b]`、`unique`、`matches_all`、`in_cidr`、布尔原子）
  `ground` 对原子仅执行绑定变量重命名。需引理：
  *引理 L1（重命名一致性）*：若 `Σ(x) = (D, i)`，则 `⟦ground_expr(x.f, Σ)⟧ρ = ⟦x.f⟧ρ[ x↦i ]`。
  由 §3.5.1 有 `⟦x.f⟧ρ = ρ(flat(domain(x), ρ(x), f))`；结合 `Σ(x)=(D,i)` 与 `ρ[x↦i]` 得
  `⟦x.f⟧ρ[x↦i] = ρ(flat(D, i, f)) = ρ(scalar_symbol(D,i,f)) = ⟦ground_expr(x.f,Σ)⟧ρ`。∎(L1)
  对原子内所有 `x.f` 应用 L1，再对运算符做同态提升（`⟦·⟧` 对 ±×/位运算/关系为同态）即得。
- **`Not / And / Or / Implies / Iff`** 直接由归纳假设与 `⟦·⟧` 的组合性（§3.5.2）得到。
- **`Forall(x̄, D, φ)` 情形**
  ```
  ⟦ground(∀x̄∈D. φ)⟧ρ
    = ⟦ And{ ground(φ, Σ[x̄↦ī], Δ) ∣ ī ∈ Tuples } ⟧ρ                     （ALG-1 定义）
    = ⋀{ ⟦ground(φ, Σ[x̄↦ī], Δ)⟧ρ ∣ ī ∈ Tuples }                          （⟦And⟧ = ⋀）
    = ⋀{ ⟦φ⟧ρ[x̄↦ī] ∣ ī ∈ Tuples }                                        （归纳假设，对每个 ī）
    = ⋀{ ⟦φ⟧ρ[x̄↦ī] ∣ ī ∈ idx(D)^k }                                      （Tuples 补齐，见下）★
    = ⟦(∀x̄∈D. φ)⟧ρ                                                       （§3.5.2 量词定义）
  ```
  其中 ★ 需说明 `Tuples` 与 `idx(D)^k` 的差异不改变取值：
  - **`distinct` 情形**：两侧都采用 `Inj(idx(D),k)`，等式成立。
  - **死变量剪枝**（`k' = 0`）：此时 `φ` 不含 `x̄`，故对一切 `ī` 有 `⟦φ⟧ρ[x̄↦ī] = ⟦φ⟧ρ`，`⋀` 折叠为同一真值，等式成立。
  - **部分出现剪枝**（`k' < k`）：未出现的变量 `x_{k'+1..k}` 不影响 `⟦φ⟧`（结构上 `φ` 中无对应 `field_access`），故 `⋀` 沿这些维度的重复不改变真值；`⋀{t ∣ ī ∈ idx(D)^k}` 是 `⋀{t ∣ ī ∈ idx(D)^{k'}}` 的 `N^{k-k'}` 次重复，`⋀` 幂等，等式成立。
  - **`FOLD-2` α-等价去重**：仅删除语义**完全相同**的重合项，`⋀` 幂等，等式成立。
  - **`FOLD-1` 常量折叠**：`⋀` 与常量 `⊤` 的消去律，等式成立。
- **`Exists` 情形** 与 `Forall` 对偶（`⋁` 幂等 + `⊥` 消去律）。∎

**推论 TH-1-C1（解集保持）** `sat(ground(φ)) = sat(φ)` 且 `M(ground(φ)) = M(φ)`（模型集相同）。由 TH-1 逐点相等立得。

**推论 TH-1-C2（反例可还原性）** `ground` 是双射于语法树的函数，且每个 `scalar_symbol` 可由 `(D, i, f)` 逆解析，故任一 `ground(φ)` 的模型可**唯一**还原为业务视图。∎

## 3.8 定理 TH-2：量词消除推论

> **定理 TH-2（Quantifier-Freeness）**
> 若 `φ` 合式，则 `ground(φ, Σ, Δ)` 的语法树中不含 `Forall` / `Exists` 节点。

**证明** 对 `φ` 归纳：`ALG-1` 的 `Forall`/`Exists` 分支返回 `And(acc)` / `Or(acc)`，其中 `acc` 的元素是递归 `ground` 的结果（由归纳假设无量词）；其余分支逐字保留框架节点，无新量词产生。归纳基：原子无量词。∎

> **推论 TH-2-C1** 生成的 SMT-LIB2 脚本中 `set-logic` 之后的公式部分**不含 `forall`/`exists` 记号**，故逻辑档位一律以 `QF_` 开头（例外见 §3.11.3 的 `QF_NRA` opt-in 路径，该路径不承诺可判定性）。

> **【补全 A-1 前置】**：上游 §2.2 声称「100% 为无量词公式」。TH-2 使该断言**从口号变为定理**，但**须附加两个前提**：(a) `W11` 预算守卫通过；(b) 用户未启用 `--allow-nonlinear`。本规范把这三点写入 G-4 的可验收表述（见 `01 §2.1`）。

## 3.9 组合爆炸与预算守卫

### 3.9.1 展开规模度量

**定义 3.9.1（Grounding 规模上界 `G`）** 递归定义

```
A(atom)          = 1                                   —— 叶子原子权重
A(¬φ)            = A(φ)
A(φ₁ ∘ φ₂)       = A(φ₁) + A(φ₂)                        —— ∘ ∈ {∧,∨,⟹,⟺}

### 3.9.4 求解期二次膨胀的诚实边界

`G(φ)` 只约束**文本/语法**规模，不约束求解器内部规模：

| 逻辑档位 | 内部膨胀机制 | 量级 |
|---|---|---|
| `QF_BV` | 位爆破（bit-blasting）为命题逻辑 | 变量数 × 位宽 |
| `QF_LIA` | 分支割平面 / 单纯形 + 整数分支 | NP-hard，实测取决于结构 |
| `QF_SLIA` | 自动机乘积 + 长度约束耦合 | 自动机状态数乘积，**主要 UNKNOWN 来源** |

故 `NFR-1` 与 `NFR-5`（UNKNOWN 率）必须联合声明，且必须绑定 `--timeout` 与 `--max-groundings` 数值（见 `10 §10.4`）。

## 3.10 定理 TH-3：可判定性与复杂度

### 3.10.1 理论片段

**定义 3.10.1（理论足迹 `T(φ)`）** `T(φ) ⊆ {LIA, LRA, BV, Str, RegLan}` 为 `φ` 中出现符号所归属的理论集合。

| 理论 | 符号 | `set-logic` 标识 |
|---|---|---|
| `LIA` | `+ - *（线性）`、`<= < >= >`、整数常量 | 参与 `QF_LIA` |
| `LRA` | `+ - *（线性）`、实数常量、`/`（常量除数） | 参与 `QF_LRA` |
| `BV` | `bvand bvor bvadd bvsub bvmul bvshl bvlshr bvult bvule …` | 参与 `QF_BV` |
| `Str` | `str.len`、字串相等/字典序、字串常量 | 参与 `QF_SLIA` |
| `RegLan` | `str.in_re`、`re.* re.+ re.opt re.union re.inter re.concat re.range re.allchar re.comp` | 随 `Str` |

### 3.10.2 主定理

> **定理 TH-3（Decidability）**
> 设 `φ` 合式（W1–W12 全部成立），`ψ = ground(φ)`。则：
> 1. `ψ` 无量词（TH-2）；
> 2. `ψ` 仅含 `T(φ)` 中的理论符号（由 `W7`/`W8`/`W9`/`W10` 强制）；
> 3. 对 `T(φ)` 的每个**单一理论组合**，`ψ` 的可满足性**可判定**；
> 4. 因此 `consistency / invariant / refines / completeness / safety` 五目标的判定问题在 `G ≤ G_max` 与 `timeout < ∞` 下**可判定**。

**证明**

1. TH-2 直接给出。
2. 由 `W8`（无非常量除数的 `/`、`div`、`mod`；无非常量×非常量的 `*`）保证不含 `QF_NIA` 符号；由 `W9` 保证正则属于正则语言（非回溯断言）；由 `W10` 保证 `in_cidr` 仅用 `bvand` 与 `=`。所有符号落在 `T(φ)`。
3. 逐理论：
   - `QF_LIA`：Presburger 算术 + `div`/`mod`/`abs`（SMT-LIB Ints 理论，全函数）。Presburger 算术可判定（Presburger 1929）；`div`/`mod` 可直接归约为带量词的 Presburger（`(div a c)` 在 `c` 为常量时可展开为有限析取），故可判定。
   - `QF_LRA`：线性实数算术可由单纯形法判定（`P` 复杂度）。
   - `QF_BV`：位向量理论等价于 `n` 位宽的模 `2ⁿ` 算术，可位爆破为命题逻辑，可判定（NP-complete）。
   - `QF_SLIA`：字串约束（连接、`str.len`、正则成员）+ 线性整数算术。**量词-free 的字串理论配合正则与长度约束可判定**（自动机 + 长度约束求解）；复杂度下界 `≥ PSPACE`，实践中为启发式求解。
   - `RegLan`：正则语言的布尔组合是有效闭包（在正则语言下封闭），可判定。
4. 由 1–3 与「有限合取/析取保持可判定性」得到。∎

### 3.10.3 组合逻辑的诚实边界（【补全 A-14】）

> **限定 TH-3a（Combination Caveat）**
> 定理 TH-3 的第 3 条是**逐理论**陈述。对**跨理论组合**（例如 `BV` 与 `LIA` 同时出现，或 `Str` 与 `BV` 同时出现），框架**不宣称**可判定性，理由：
> - 上游 v2.0 的 `deduce_smt_logic` 会推导出 `QF_BVLIA` 等**扩展组合逻辑名**。该名称在 SMT-LIB 逻辑清单中的确切收录状态、以及其在 Z3 / CVC5 / Bitwuzla 中的实际支持度**存在版本差异**；
> - 硬编码逻辑名会导致「路由到不支持该逻辑的求解器 → 报错退出」，这正是上游 FR-8 想避免的问题。
>
> **工程化解法（DD-3.2 能力探测替代硬编码）**：框架在启动时对每个后端执行**逻辑冒烟探测**（`ALG-3 probe_logic`，见 `06 §6.4`），以**实测**构建 `SolverCapability` 矩阵：
> - 探测**通过**：该组合逻辑被视为「本环境下可判定」，允许 `Pass` 判定；
> - 探测**失败**（求解器报 `(error "unsupported logic")` 或返回 `unknown`）：该逻辑档位被标记 `UNKNOWN_RISK`，门禁在该目标上**只接受 `UnknownReviewRequired`**，**禁止**输出 `Pass`。
>
> 该设计把「依赖标准条文的脆弱假设」替换为「依赖运行期实测的可信声明」，与 G-8 的诚实阻断哲学一致。

### 3.10.4 复杂度与性能预算

| 目标 | 判定过程 | 理论复杂度 | 主导风险 |
|---|---|---|---|
| `consistency` | 一次 SAT 查询 + 核心最小化（`O(A)` 次重查，`A` = 断言数） | NP-hard + `O(A)` 倍 | 大 `A` 时核心最小化成为耗时主因 |
| `invariant` | 一次 SAT 查询 | NP-hard | 反例搜索深度 |
| `refines` | 两次 SAT 查询（`Q1`/`Q2`，见 `06 §6.3.3`） | 2 × NP-hard | 边界层（如 `[80,1023]`）区间求解 |
| `completeness` | 一次 SAT 查询 | NP-hard | 分支数 × 域规模 |
| `safety` | 一次 **无量除** SAT 查询 | NP-hard（除数所在理论） | 低（不含除法，规模最小） |
| **编译期** | 解析 + 检查 + `G` 静态计算 | `O(|φ|)`（`G` 计算不展开） | 无 |
| **展开期** | `ALG-1` | `O(G(φ) · |φ_atom|)` | `G_max = 10⁶` 时约需 10⁷–10⁸ 步；**须分块 + 惰性 `String` 拼接**（`05 §5.7`） |
| **核心最小化** | deletion-based | `O(A)` 次求解 | 默认关闭，`--minimize-core` 开启并受独立预算约束 |

> **【补全 C-8】** 上游 NFR-2「1000 行 DSL 编译耗时 < 500ms」在 `G_max = 10⁶` 时**不可保证**：`O(G)` 的展开本身就可能超过 500ms。本规范拆分该指标为两条（见 `10 §10.4 BENCH-2`）：
> - `NFR-2a`：**检查阶段**（不含展开）1000 行 DSL < 200ms；
> - `NFR-2b`：**含展开**在 `G = 10⁶` 上界时 < 500ms；`G ∈ (10⁶, 10⁷]` 线性外推每 `10⁶` 追加 400ms。

## 3.11 定理 TH-4：除法线性化与全域性义务

### 3.11.1 问题的数学本质（【补全 A-11 / A-12 / C-5，严重级 P0】）

SMT-LIB 的 `Real` 除法 `/` 与 `Int` 除法 `div`、取模 `mod` 是**全函数**：`(/ a 0)`、`(div a 0)`、`(mod a 0)` **不报错**，其取值在标准中**未被指定（unspecified）**，由求解器自由选择。

> **后果（关键洞察）**：若分母可能取 0，则
> ```
> ⟦a / b⟧ρ  在 ρ(b) = 0 时是一个任意值
> ```
> 于是 `(/ a b) > 0.5` 这样的断言在分母为 0 的赋值上**可能被任意判真或判假**，**任何基于该公式的 PASS 判定都可能是假证明（unsound）**。
>
> 这就是「除法全域性义务（Well-Definedness Obligation）」必须被**独立验证**的根本数学理由——上游 v2.0 的 `safety` 目标直觉正确，但**未给出该理由，也未定义义务的生成规则**。

### 3.11.2 义务生成（`ALG-2 collect_div_obligations`）

```
ALG-2  collect_div_obligations(P) → List<Term>
遍历 ground(P) 的 AST，收集每一处 Div/Mod 节点的分母位置子式 b：
    obl(P) ≜ ⟨ b₁, …, b_k ⟩      （按 AST 前序遍历顺序，确定性）
若 k = 0：obl(P) = ⟨⟩  ⇒  safety 义务为 ⋀∅ = ⊤（报告标注 safety_vacuous）
```

**义务的数学陈述**（`safety` 目标的形式化定义）

```
safety(P)  ≜  ∀m ∈ M.  R_P(m)  ⟹  ⋀_{j=1..k} ( b_j(m) ≠ 0 )

其中 R_P(m) ≜ ⋀{ ⟦ground(r)⟧m ∣ r ∈ rules(P) }
```

> **【补全 A-11】**：上游 §4.1 的 `safety` 编码写作 `(assert (= Denom 0))`，其中的 `Denom` **从未被定义**（既不是 DSL 关键字，也无生成规则）。本节以「从 AST 收集全部除/模节点」定义之。

### 3.11.3 定理 TH-4：线性化重写

在义务 `b_j ≠ 0` 被**独立解除**（即 `safety` 目标 `Pass`）之后，含 `Real` 除法的比较可被**等价**重写为无除法形式：

> **定理 TH-4（Division Linearization）**
> 对 `a, b, c ∈ ℚ`，`b ≠ 0`，有
> ```
> (D1)  a / b = c   ⟺   a = b·c
> (D2)  a / b ≠ c   ⟺   a ≠ b·c
> (D3)  a / b <  c  ⟺   ( b > 0 ∧ a < b·c )  ∨  ( b < 0 ∧ b·c < a )
> (D4)  a / b ≤  c  ⟺   ( b > 0 ∧ a ≤ b·c )  ∨  ( b < 0 ∧ b·c ≤ a )
> (D5)  a / b >  c  ⟺   ( b > 0 ∧ a > b·c )  ∨  ( b < 0 ∧ b·c > a )
> (D6)  a / b ≥  c  ⟺   ( b > 0 ∧ a ≥ b·c )  ∨  ( b < 0 ∧ b·c ≥ a )
> ```

**证明** 以 (D3) 为例（其余同构）。
`(⟹)` 设 `a/b < c`。因 `b ≠ 0`，两种情形：
- `b > 0`：`a/b < c ⟹ a < b·c`（两边乘正数保序）。得 `b>0 ∧ a<b·c`。
- `b < 0`：`a/b < c ⟹ a > b·c`（两边乘负数**反序**）。得 `b<0 ∧ b·c < a`。
`(⟸)` 反之，若 `b>0 ∧ a<b·c`，两边除正数 `b` 得 `a/b < c`；若 `b<0 ∧ b·c<a`，两边除负数 `b` 得 `a/b > b·c/b = c`。∎

**（D1）证明** 设 `b ≠ 0`。`(⟹)` `a/b = c ⟹ a = (a/b)·b = c·b`。`(⟸)` `a = b·c ⟹ a/b = b·c/b = c`。∎

> **线性化侧条件 `LinDiv(a, b, c)`**
> 右式引入乘积 `b·c`。为使 TH-4 真正带来可判定性收益，必须
> ```
> LinDiv(a, b, c) ≜ isConst(b) ∨ isConst(c)
> ```
> 即**分母与比较右侧至少一方为编译期常量**。若 `LinDiv` 不成立（如 `x / y > z`，三者皆变量），则 (D3) 右式含 `y·z` 为非线性 ⇒ `E-NONLINEAR`。
>
> 典型可线性化案例（上游 `RiskRatioPolicy` 的场景）：
> `loss / exposure > 1/2` ⇒ `(exposure > 0 ∧ 2·loss > exposure) ∨ (exposure < 0 ∧ 2·loss < exposure)` —— `2` 为常量，`2·loss` 线性 ✔ 仍在 `QF_LIA`。

### 3.11.4 「`div`/`mod` 不可线性化」定理

> **命题 3.11.1（Non-Linearizability of floor-division）**
> 对整数 `div` / `mod`（floor 语义），不存在仅用 `+`、`-`、常量乘与线性关系表达的等价重写。
> **理由**：`z ↦ ⌊z/c⌋` 是**分段常值阶跃函数**，其图像不是半线性集的可定义函数；`(div a c)` 在 `c > 1` 时取 `⌊√·⌋`-型不连续值。形式化地，`{ (a, q) ∣ q = div(a, c) }` 不是 `(ℤ², +, ≤)` 中的半线性集（Presburger 可定义集），而后者只能在有界区间上分段线性逼近。

**结论（编码策略）**

| 构造 | 处理 |
|---|---|
| `(div a c)`，`c` 为**常量**，`c ≠ 0` | **允许**，直接编码 `(div a c)`。SMT-LIB Ints 理论含 `div`/`mod`/`abs`，Z3/CVC5 在 `QF_LIA` 下支持（**须由能力探测确认**，见 `06 §6.4`） |
| `(mod a c)`，同上 | 同上 |
| `(div a b)`，`b` **非常量** | **编译阻断** `E-NONLINEAR`。诊断提示「请改用 `Int [min..max]` 上的分段枚举，或将除数固化为常量」 |
| `(a / b)`，`b` 常量且 ≠ 0 | 允许；编码 `(/ a b)` |
| `(a / b)`，`b` 非常量，且出现在比较中，且 `LinDiv` 成立 | **自动线性化**（TH-4），输出无除法形式 |
| `(a / b)`，`b` 非常量，且 `LinDiv` 不成立 | `E-NONLINEAR`；仅 `--allow-nonlinear` 放行，此时逻辑档位降为 `QF_NRA`，目标强制 `UnknownReviewRequired`（不承诺可判定，见 TH-3a） |

> **【补全 A-12】**：上游把 `safety` 的语义描述为「验证算术表达式安全性（无除零越界）」，但**从未指出** `div`/`mod` 是 floor 函数因而不可线性化，也未给出「线性化重写」这一关键使能技术。缺此技术，`RiskRatioPolicy` 这类含变量分母的策略**只能被拒绝或降级为 UNKNOWN**；有此技术，则可在保持 `QF_LIA` 可判定性的同时支持真实的风控比率策略。这是本次补全中对**产品可用性**影响最大的单点。

### 3.11.5 `safety` 目标的编码（引出，详情见 `06 §6.3.5`）

关键设计：**安全性查询本身不含任何除法**。

```
(assert Bnd)
(assert R_P)                                    —— 策略断言（若其中含常量除数 div，仍保留）
(assert (or (= b₁ 0) … (= b_k 0)))              —— 义务的否定
(check-sat)                                     —— UNSAT ⇒ PASS
```

因为 `b_j` 是**线性表达式**（由 `W8` 保证），该查询保持在 `LIA`/`LRA`，**不因除法而降级**。这使「除法」与「可判定性」在架构上解耦。

## 3.12 定理 TH-5：CIDR 掩码等价

### 3.12.1 定义

```
CIDR 块     block(n₀, p) ≜ { ip ∈ {0..2ⁿ−1} ∣ ⌊ip / 2^(n−p)⌋ = ⌊n₀ / 2^(n−p)⌋ }
掩码        mask(p)       ≜ 2ⁿ − 2^(n−p)          (1 ≤ p ≤ n)      mask(0) ≜ 0
网络地址    net(n₀, p)    ≜ n₀ & mask(p)
```

其中 `n` 为地址位宽（IPv4 `n = 32`，IPv6 `n = 128`）。

### 3.12.2 定理

> **定理 TH-5（CIDR Masking Equivalence）**
> 对 `0 ≤ p ≤ n`、`n₀ ∈ {0..2ⁿ−1}`：
> ```
> (ip & mask(p)) = net(n₀, p)   ⟺   ip ∈ block(n₀, p)
> ```

**证明**
记 `s = n − p`、`M = 2ⁿ − 2^s`、`E = n₀ & M`。
*（⟸）* 设 `⌊ip/2^s⌋ = ⌊n₀/2^s⌋ = q`。则 `ip = q·2^s + r`、`n₀ = q·2^s + r₀`，`0 ≤ r, r₀ < 2^s`。
`E = n₀ & M`：`M` 的二进制为高 `p` 位全 1、低 `s` 位全 0，故 `n₀ & M = q·2^s`（把低 `s` 位清零）`= ⌊n₀/2^s⌋·2^s`。
`ip & M = ⌊ip/2^s⌋·2^s = q·2^s = E`。✓
*（⟹）* 设 `ip & M = E = q·2^s`（`q = ⌊n₀/2^s⌋`）。又 `ip & M = ⌊ip/2^s⌋·2^s`，故 `⌊ip/2^s⌋ = q`。✓
（`p = 0` 时 `M = 0`，`E = 0`，两式皆恒真，等价成立；`p = n` 时 `M = 2ⁿ−1`，`E = n₀`，`ip & M = ip`，即 `ip = n₀`，与 `block(n₀,n) = {n₀}` 一致。）∎

### 3.12.3 编码与校验规范

| 项 | 规范 |
|---|---|
| DSL 形态 | `in_cidr(e, "A.B.C.D/p")`（IPv4）/ `in_cidr(e, "2001:db8::/32")`（IPv6，含 `:` 者判为 v6） |
| 排序要求 | `e : BV(32)` 配 IPv4；`e : BV(128)` 配 IPv6；否则 `E-CIDR-WIDTH` |
| 前缀范围 | IPv4 `p ∈ [0,32]`；IPv6 `p ∈ [0,128]`；越界 `E-CIDR-SYNTAX` |
| 字面量校验 | IPv4：4 段十进制 `0..255`，无前导零（除 `0` 本身）；IPv6：RFC 4291 压缩形式，**禁止** zone-id（`%eth0`）、**禁止** IPv4-mapped 混写（`::ffff:1.2.3.4` 须显式改写为 v6 形式）；非法 `E-CIDR-SYNTAX` |
| 掩码生成 | `p = 0 ⇒ 0`；`p > 0 ⇒ (2ⁿ − 2^{n−p})` |
| 字面量常量性 | CIDR 字面量**必须**是字面量（不许变量/拼接），保证 `W8` 线性性下的零成本编码 |
| SMT 编码 | `(= (bvand <e> (_ bvMASK n)) (_ bvNET n))`（使用十进制 `(_ bvN W)` 形式而非 `#x`，规避不同求解器对十六进制宽度的隐式截断差异） |
| 符号性 | 一律无符号；`bvand` + `=` 无符号歧义（N-3） |
| 附加原语 | `in_range(e, "lo", "hi")` ⇒ `(and (bvule lo e) (bvule e hi))`，用于非对齐地址段；要求 `bvule(lo,hi)` 否则 `E-CIDR-SYNTAX` |

> **【补全 A-9】**：上游仅给出 `in_cidr(ip_expr, "10.0.1.0/24")` 与一个 IPv4 示例，未定义 IPv6、前缀 `0`、前缀 `n`、非法字面量、排序匹配、以及 `#x` 与 `(_ bvN W)` 的编码选择。本节全部补齐，并把掩码公式提升为定理 TH-5。

## 3.13 定理 TH-6：正则子语言转译保持

### 3.13.1 子语言 `R_sub`（允许）

| PCRE 片段 | 语义 | SMT-LIB `RegLan` 转译 `τ` |
|---|---|---|
| 字面字符 `c`（可打印 ASCII ∪ 基本多文种平面单码点） | `{c}` | `(str.to_re "c")` |
| `.` | `Σ`（任意单码点） | `re.allchar` |
| `[abc]` | `{a}∪{b}∪{c}` | `(re.union (str.to_re "a") (str.to_re "b") (str.to_re "c"))` |
| `[^abc]` | `Σ ∖ {a,b,c}` | `(re.comp (re.union (str.to_re "a") …))` |
| `[a-z]` | `{c ∣ a ≤ c ≤ z}` | `(re.range "a" "z")` |
| `\d` | `[0-9]` | `(re.range "0" "9")` |
| `\w` | `[A-Za-z0-9_]` | `re.union` 三段的组合 |
| `\s` | `[ \t\n\r\f\v]` | 枚举 `re.union` |
| `r₁ r₂`（连接） | `L(r₁)·L(r₂)` | `(re.concat τ(r₁) τ(r₂))` |
| `r₁\|r₂` | `L(r₁) ∪ L(r₂)` | `(re.union τ(r₁) τ(r₂))` |
| `r*` | `L(r)*` | `(re.* τ(r))` |
| `r+` | `L(r)⁺` | `(re.+ τ(r))` |
| `r?` | `L(r) ∪ {ε}` | `(re.opt τ(r))` |
| `r{n}`，`1 ≤ n ≤ 64` | `L(r)ⁿ` | `n` 份 `τ(r)` 的 `re.concat` 展开 |
| `r{n,}`，`n ≤ 64` | `L(r)ⁿ · L(r)*` | `(re.concat τ(r)ⁿ (re.* τ(r)))` |
| `r{n,m}`，`n ≤ m ≤ 64` | `⋃_{i=n..m} L(r)ⁱ` | `re.union` 展开 |
| `^r$` | 全串匹配 | `τ(r)`（**冗余**：`str.in_re` 天然全串匹配） |
| `\(` `\)` `\[` `\]` `\\` `\.` `\"` `\*` `\+` `\?` `\|` `\{` `\}` `\^` `\$` | 转义字面字符 | `(str.to_re "<c>")` |
| `\xHH` / `\uHHHH` | 码点 | `(str.to_re "<码点>")` |

### 3.13.2 拒绝清单（`E-REGEX-NONREGULAR`）

| 构造 | 拒绝理由 |
|---|---|
| 反向引用 `\1`…`\9`、`\k<name>` | 非正则语言（指数级描述能力），不可自动机化 |
| 前瞻 `(?=` `(?!`、后顾 `(?<=` `(?<!` | 不可判定（上游 v2.0 已正确识别，但仅提及「前瞻/后顾」，未列反向引用） |
| 词边界 `\b` `\B` | 依赖上下文，非纯正则 |
| 递归/子程序 `(?R)` `(?1)` `(?&name)` | 图灵完备，违反 NG-1 |
| 占有量词 `*+` `++` `?+` `{n,m}+` | 匹配语义依赖回溯顺序，无自动机等价 |
| 原子组 `(?>…)` | 同上 |
| 条件 `(?(cond)yes\|no)` | 图灵完备 |
| POSIX 字符类 `[[:alpha:]]` | **是**正则，但 SMT-LIB `RegLan` 无对应语法。归为 `E-REGEX-UNSUPPORTED`（与 `E-REGEX-NONREGULAR` 区分，前者可建议改写） |
| Unicode 属性类 `\p{L}` | 同上（`E-REGEX-UNSUPPORTED`），建议改写为显式 `re.range` 枚举 |
| 嵌套量词展开超预算（`r{n,m}` 且 `n·|τ(r)| > 4096`） | 展开爆炸，`E-REGEX-BUDGET` |

### 3.13.3 定理

> **定理 TH-6（Regex Transpilation Preserves Language）**
> 对一切 `r ∈ R_sub`，记 `L(·)` 为语言函数（`L : Regex → 𝒫(Σ*)`），有
> ```
> L( τ(r) )  =  L( r )                       （在 RegLan 的标准语义下）
> ```

**证明** 对 `r` 的结构归纳，逐构造对照表 3.13.1：基础字符/字符类由 `str.to_re`、`re.range`、`re.union`、`re.comp` 的标准语义直接给出；连接/并/闭包由 `re.concat`/`re.union`/`re.*`/`re.+`/`re.opt` 的标准语义给出；计数构造由 `L(r)ⁿ = L(rⁿ)`（连接幂的定义）、`L(r{n,}) = L(r)ⁿ·L(r)*`、`L(r{n,m}) = ⋃_{i=n..m}L(r)ⁱ` 的标准正则代数律给出；`^…$` 由 `str.in_re` 的全串语义（`⟦e matches_all[r̄]⟧ρ = ⟦e⟧ρ ∈ ⋂L(r)`）给出冗余性。∎

**推论 TH-6-C1** `matches_all [r₁, …, r_k]` 的编码
```
(str.in_re e (re.inter τ(r₁) (re.inter τ(r₂) (… τ(r_k))))
```
在 `k = 0` 时退化为 `⊤`（对应 `⋂∅ = Σ*`），在 `k = 1` 时退化为 `(str.in_re e τ(r₁))`。其语义等价于 `⟦e⟧ρ ∈ ⋂_{r}L(r)`，由 `L(re.inter R₁ R₂) = L(R₁) ∩ L(R₂)` 与 `str.in_re` 语义立得。∎

> **【补全 A-10，严重级 P0】** 上游 v2.0 **通篇没有正则转译器**：FR 表层给出 `matches_all` 编译为 `(re.inter ...)` 的**目标**，但既未定义允许的正则子集 `R_sub`，也未定义 PCRE 语法到 SMT-LIB `RegLan` 语法的**映射表**，更未列出拒绝清单。仅有一句「规避 PCRE 不可判定前瞻」。缺此转译器，`matches_all` 根本无法落地为 SMT-LIB2 文本。本节补齐 `R_sub`、映射表 `τ`、拒绝清单与保持定理 TH-6。
>
> **另注**：编码一律显式使用 `str.to_re "c"` 而**不**依赖求解器对裸字符串的字串自动强制转换（CVC5 支持隐式强制、Z3 部分支持），以保证跨求解器可移植（`06 §6.5`）。

## 3.14 定理 TH-7：编码充分性（总纲）

> **定理 TH-7（Encoding Adequacy，总纲）**
> 设规范 `S` 合式，`P` 为 `S` 中某策略，`V` 为 `S` 中某个 `verify` 声明，`Q(V)` 为按 `06 §6.3` 生成的 SMT-LIB2 查询，`verdict(Q)` 为其首行判定（`sat`/`unsat`/`unknown`），`π(V)` 为该目标的数学命题（§3.11.2 与 `06 §6.3` 逐条给出）。则
> ```
> (i)   verdict(Q(V)) = unsat  ⟹  π(V) 成立
> (ii)  verdict(Q(V)) = sat    ⟹  ¬π(V) 成立，且 (get-model) 返回的模型 m 满足 m ⊭ π(V)
> (iii) verdict(Q(V)) = unknown ⟹  不作任何断言（诚实阻断）
> ```
> 即编码是**可靠（sound）**且**相对完备（complete modulo solver completeness）**的。

**证明策略**（完整证明拆入 06 的逐式论证，Lean 机械化见 `12 §12.4 TH-SMT-3`）
对每个目标逐一验证「`Q(V)` = `Bnd ∧ ¬π'(V)`」形式，其中 `π'(V)` 是 `π(V)` 的 Skolem 化前提：
1. 由 TH-1-C1，`R_P` 的 SMT 断言与 `⟦·⟧` 语义逐点相等；
2. 由 `Bnd` 的特征谓词定义（3.2.6），`(assert Bnd)` 恰好刻画 `m ∈ M`；
3. 因此 `Q(V)` 可满足 ⟺ `∃m ∈ M. ¬π(V)(m)`；
4. `unsat(Q(V))` ⟺ `∀m ∈ M. π(V)(m)` ⟺ `π(V)`；`sat(Q(V))` 时求解器给出的模型即 `¬π(V)` 的见证。
（各目标 `π` 与 `π'` 的具体对应见 `06 §6.3` 的逐式表，包括 `refines` 的双查询分类、`completeness` 的 `branch` 化归、`safety` 的义务提取。）∎

**说明**：`(iii)` 是**核心安全性质**——`unknown` 永不被解释为 `unsat`，因此不会产生假证明（unsound PASS）。它由 §6.8 的响应解析状态机与 `overall_status` 合并格（`00 §0.4.2`）双重保障。
